## 2. いちばん大事な注意: 改名をまたいだ同一シード比較は無効

カードIDを変えると、**探索の乱数の並びが変わる**。

理由は `rust/src/agents.rs::sort_by_id` にある。planner は先読みの前に
「相手の手札にありうるカード」を並べてから混ぜるが、その並べる順が
**card_id の文字列順**である（順序を固定しないと情報が漏れるため・
`determinization_leak.md`）。IDの綴りが変われば並び順が変わり、
同じ乱数でも別の並びが出る。

**これは「別のシードで回した」のと同じであり、AI が強くも弱くもなっていない。**
ただし:

> **改名前に取った結果と、改名後の結果を、同じシードだからといって並べてはならない。**
> 比べたいときは**両方を新ID体系で取り直す**こと。

影響を受ける記録: ラダー（`results/ladder.json`）、発見ループの結果
（`results/discoveries/`）、DRL 各段階の評価値。**数字が間違っているわけではない**が、
「同じシードだから対にできる」という前提が切れている。

なお**ランダム自己対戦（スモーク）は影響を受けない**。SD02 のスモークは
改名の前後で平均ターン・最小・最大まで完全に一致することを確認した。

## 3. 秧秧Lv2 の訂正はどれくらい効いたか

実カード（`cards/SD01-003_秧秧_LV2.png`）は
「【対抗】**相手が**赤色のカードで対抗した場合、相手はコスト1を支払ってもよい。
支払わなかった場合、相手はダメージ3を受ける。」

engine は「**自分が**赤で対抗した場合」だった。
**相手の赤を咎めるカウンターが、自分の赤を後押しする追加打点に化けていた。**

測った結果（詳細は D-062 §3）:

- **ゲームの均衡は動かない。** SD001 ミラー4,000局の先攻勝率は
  訂正前 0.505 ±0.015 → 訂正後 0.505 ±0.015。差は ±0.000。
  ミラー戦なので対称であり、動かないのが正しい。
- **でもほとんどの局に触れている。** 同じシードの4,000局のうち
  **2,963局は展開が変わった**。札の発動回数は 1局 1.88 → 2.04 回に増えた。
- **AI 同士の力関係は動いたと言えない。**
  champion vs H が +0.005 ±0.016、champion vs 貪欲が -0.013 ±0.022。
  どちらも差の区間が 0 をまたいでいる。

**結論として、過去のラダーや発見ループの結論をいますぐ捨てる必要はない。**
ただし §2 のとおり同一シードでの対比較はできないので、
次にそれらを回すときは**新ID体系で取り直した数字を対照に使う**こと。

一方で、**デッキ構築の話には影響する可能性がある**。
「秧秧Lv2 を立てて自分から赤で殴る」型の評価は、訂正前の誤った札で測られていた。
発見ループを次に回すときは、そこだけ結論が動きうると思っておく。

## 4. 学習済みネットの扱い（触る前に読む）

### 4-1. 何が起きたか

`encode.py` は観測を「カード1種につき1枠」並べた固定長の数列にする。
`AC-001` を消すとカード種数が 35 → 34 になり、
**観測 608 → 596 / 行動 113 → 111** と入力の形が変わった。

保存済みネット（608入力）をそのまま読ませると、
運が良ければ落ちるが、悪ければ**黙って別のカードの枠を読む**。

### 4-2. どう直したか

`scripts/migrate_nets_d062.py` で、保存済み3本
（`drl_sd001_s1` / `drl_sd001_s2r1` / `drl_sd02_s1`）から
**AC-001 に対応する列だけを切り落とした**。

AC-001 はどのデッキにも入っていないので、その枠の入力は**常に 0** である。
0 が掛かる重みは何であっても出力に寄与しない。したがってこれは
「学習し直し」ではなく「使われていない列の切り落とし」であり、
**実数の計算としては値がまったく変わらない**。

float32 では足し算の順序が変わるぶん最後の桁に丸め誤差が出る（相対 1e-6 前後）ので、
**それで選ぶ手が変わらないこと**を実際の対局で確かめた:
champion 同士24局（seed 330000..330023）で **digest が24局とも一致**した
（digest はその局の全決定を畳み込んだハッシュ。一致＝毎手同じ手を選んだ）。

### 4-3. これから気をつけること

- **符号化 版2 で作ったデータセットは版3 と混ぜてはならない。**
  `results/drl/*.manifest.json` が指すものがそれである。
  DRL の学習をやり直すなら、記録から取り直すこと。
- `drlnet.Net.load` に**寸法と版の検査**を入れた。合わなければその場で落ちる。
  意図的に古い版を読みたいときだけ `strict=False` を渡す。
- **カードを1枚足すたびに同じ問題が起きる**。未登録13枚を入れるときは
  `ENCODING_VERSION` を上げ、ネットは移行するか学習し直す。
  移行できるのは「常に 0 の枠を切る／足す」場合だけである
  （新カードを足す場合は、新しい枠の重みを 0 で初期化すれば同じ理屈が使える）。
