## TA-7 TE-5（M1）を終えた: トレース点の口と、仕様書から変えた点（2026-09-20・急ぎ度: 中・状態: **済**。`engine/app/TASKS_APP.md` の Done「送り箱 TA-1〜TA-7 を受けた」を確認して 2026-09-21 に閉じた）

**口**: `from meicho import trace` → `with trace.tracing(sink): s2 = apply(s, actions)`。`sink(kind, info, s)`。`s` は解決途中の生の状態（読むだけ・保持しない）。
sink は `contextvars` で持つので、別スレッドの `apply` は流れ込まない。**同じスレッドの同じ with の中で AI に考えさせると、AI の探索の `apply` も流れ込む**ので、AI は with の外で呼ぶこと。
sink の例外はそのまま呼び出し元へ伝わる。

**kind と info**（名前は仕様書どおり）
- `action`: `player`・`action`（合法手の辞書の写し）・`phase`（当てる前）
- `step`: `what` が `"op"`（`owner`・`op`・`card`・`card_kind`）／`"skill"`（`player`・`card`・`card_kind`・`skill_index`・`timing`）／`"resume"`（`resume`）
- `wait`: `phase`・`players`・選択待ちなら `choice_kind`
- `game_over`: `outcome`（勝者の席・引き分けは -1）・`reason`（`"life"`・`"deck_out"`・`"deadlock"`）
- `draw`: `player`（1 枚ごと）／`refresh`: `player`
- `damage`: `player`・`amount`（軽減・加算の後）・`dealer`・`source`（`[種類, カード番号]` か null）。0 以下に削られたら出ない／`heal`: `player`・`amount`（実際の増分）
- `reveal`: `owner`・`cards`・`audience`（`"all"` か席の番号）・`zone`。出るのは `search_deck`（見つかったときだけ）・`reveal_top_to_hand`・`reveal_n_take_matching`・`peek_opponent_hand`・B-9 の 5 か所

**仕様書から変えた点**（どれも復元のしやすさのため。都合が悪ければ TE-n で）
1. `action` は**当てる前**に出す。同時手番（準備・マリガン・対抗の提出）は 2 席ぶんを**席の昇順でまとめて先に**出す。次のトレース点までの差分が、その行動の結果になる
2. `step` も**処理に入る前**に出す。選択で中断して再開すると、同じ `op` がもう一度出る。`skipped` の旗は付けていない（その `op` のあとの差分が空なら読み飛ばし）
3. `reveal_top_to_hand` の `reveal` は、引き終えた**後**に出る（その直前に `draw` が枚数ぶん出ている）。`zone` は `"action_deck"`
4. マリガンの引き直しは `draw` を出さない（公式のドローではなく `_draw` を通らない）。マリガンの `action` のあとの差分に出る
5. §4.4 の任意の 3 つ（判定の結果・コストの支払い・ターンの開始）は入れていない

確かめたこと: トレースあり・なしで毎手の状態が一致（SD001・SD02・BP01 の仮デッキ）／`bench_agents.py` の指紋 3 種と速度が不変／Python↔Rust の毎手一致が通る。検査は `tests/test_trace_m1.py`（19 件）。

欲しい結果: 受けたことと、アプリ側の記録器がこの口で組めたかが `engine/app/TASKS_APP.md` から分かること。
