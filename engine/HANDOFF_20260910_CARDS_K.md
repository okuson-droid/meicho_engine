### 0.3 前提の裁定（推しで進める。異なる裁定なら読み替える）

1. **登録の順序は「末尾に追記」**。`cards.py` の登録順が `ACTION_IDS`/`CHARA_IDS` の添字＝Rust の `CardDb` の順なので、既存 52 枚の添字を動かさないために新カードは既存の後ろに足す（ID 順に並べ替えない）。**推し: 追記**。理由: ネットの移行が「0 の列を末尾に足す」だけになり、既存の添字が不変であることを検査で言える。
2. **3 番号の枠は今登録する**。`ActionCard(..., unverified_fields=(...全欄...), skills=())` の空カードとし、`dedicated_to=None`・色/コスト/スピード/ダメージは仮値 0。**どのデッキリストにも入れない**検査を置く（`test_unverified_cards_are_in_no_decklist`）。**推し: 登録する**。理由: 後で埋めるとき `ENCODING_VERSION` をもう一度上げずに済む。
3. **ネットの移行は D-062 の道具の逆向き**（`scripts/migrate_nets_d062.py` は列を削った。本便は 0 の列を**挿す**）。SD001/SD02 のデッキに無いカードの入力は常に 0 なので、出力は数学的に不変。移行の対象は `results/models/` 以下で `obs_dim == 596` のすべて（champion の V_4'・蒸留した π・旧 champion の V_3・便 E-0 以前の世代を含む）。**原本は消さず** `*.enc3.bak.json` を並べて残す。**推し: 全部を移行し、champion の指す名前は変えない**（測定の JSON がその名前を指している）。
4. **fingerprint 4 種の扱い**。手が 1 手も変わらないことは digest（4,000 局）で示す。fingerprint（sha256 の先頭 16 桁）が**手は同じなのに動いた**場合は、動いた原因が「ネットの推論の丸め（rel 1e-6 以下）」だけであることを示したうえで、新しい値を D-079 に「作り方つき」で記録する（便 D 前半で `7251a931d252a57a` を作り直したときと同じ扱い）。**手が変わったら不合格**（登録簿の追加が打ち方に漏れている）。**推し: この 2 段構え**。
5. **未定義事項の当面の実装**。K-2 以降で条文が要る箇所は、K-0 で列挙した推しの解釈で実装し、該当する `Skill` に `unverified=True` を立てて「裁定待ち」を機械可読にする。**マスターが公式ルール（発売後の同梱マニュアル・公式 Q&A）で確かめた時点で外す**。**推し: 推しで実装＋旗**。理由: 旗が無いと「確認済み」と混ざる（作業規約 4）。
6. **画像なしのカード**。`webapp/images.status()["missing"]` を落とす検査は「BP01 で画像が無い番号の許容リスト」を `cards/` 側に持たせて通す（`cards/BP01_NO_IMAGE.json`。取得した 13 番号は画像がある）。アプリは画像が無ければ名前＋効果文の札を描く。**推し: 許容リスト**。
7. **`heuristic.LEADER_COLOR`（キャラ名 6 件の直書き・D-047 監査の「高」）** は本便で `cards.py` から派生する形に直す。H の打ち方が SD001/SD02 で不変であることは fingerprint `6e39c2aa4b35d876` が守る。**推し: 直す**。
8. **PC の Rust 再ビルドは 1 回**。便 K は `engine.rs`/`cards.rs`/`state`/`encode.rs` を変えるので再ビルドが要るが、依頼は**便 C の交代判定の結果が出たあと**に、交代の分と 1 つの wheel にまとめる（計画書 §4.1 の便 A＋C と同じ流儀）。**推し: まとめる**。それまでマスターの PC では Rust 側の検査が理由つき skip になる（正常）。

## 7. 転びやすいところ（症状 → 意味 → 直し方）

- `drlnet.Net.load` が「符号化の形が合わない」で落ちる → 登録簿を変えたのにネットを移行していない、か、古い `cards.py` で移行済みネットを読んでいる → `migrate_nets_k.py --check` で対象を確かめ、順序（§1）を守る。
- T-K-1 が落ちるのに新カードは SD のデッキに無い → 新しい状態欄の既定値が対局に漏れている（例: `damage_taken_mod` の初期値が 0 でない・`_begin_turn` の繰り越しが既存の `clash_winner` を上書きしている）→ 欄を 1 つずつ戻して二分する。
- Rust の毎手一致が「同じ手だが点数が違う」で落ちる → `db.action_rank` の順序（ID の文字列順）と Python の `sorted` がずれた → 新 ID の綴り（`BP01-0xx`）が既存と同じ幅か確かめる。
- `test_clone_copies_every_field` が落ちる → 新しい欄を `clone`/`to_json` に足していない。
- 【登場】が準備で誘発して手札が空のまま「加えてもよい」の選択肢が出る → u1 の推しに反している。
- `test_card_images.py` が `unused` で落ちる → 画像がある 13 番号のうち登録していないものがある。
- 仮デッキのスモークで打ち切りが出る → 【優勢】＋回収の循環（超制限＋メェ、助けて）が疑われる。`play_game` のターン上限に当たった局面を `BP01_NOTES.md` に記録し、便 G への申し送りにする（ルールの問題ではなく仮デッキの問題）。
- PC で Rust の検査が skip → 再ビルド前なので正常。**便 C の交代判定の結果を待ってから 5 点セットで依頼する**。
