# 汎用 AI 段階1B後「観測・符号化の費用分離」の結果（D-120・2026-09-22）

計画書 `GENERALIST_AI_REVIEW_D086.md` §6「段階1B後」の便。**勝率は測っていないし、採否にも使わない。**
完了条件は「ボトルネックと対象構成の実測費用を説明できること」。

## 0. 結論

1. **時間の 8 割はニューラルネットの掛け算である。**champion（SD001 同型）の 1 局では、命令数の **82%** が `net::Dense::forward`（全結合層の計算）だった。
   そのうち大部分（**75〜77%**）は、探索の中で担当外の手を埋める**代打ち π**（`pi_small64_e10`）の呼び出しから来ている
2. **観測の符号化は 7%、Python と Rust の受け渡しと記録の書き出しは 1% 未満。**1 局は Rust の中で閉じていて、Python からの呼び出しは対局列ごとに 1 回しかない。
   JSON・言語間の変換・観測のバイナリ化は**ボトルネックではない**（計画書の「一律には採用しない」を実測で裏づけた）
3. 時計でも同じ順になる: 代打ち π を外すだけで 1 局 **11.2 秒 → 2.6 秒（4.2 倍速）**、ネットを全部外すと **0.10 秒（約 116 倍速）**
4. **ネットを使わない構成では、状態の更新と複製が主役になる**（`apply` が対局部分の約 4 割、状態の複製と破棄が約 1.6 割、合法手の列挙が約 1.1 割、メモリ確保と解放が多い）
5. 決定性: 評価の先頭 20 局を 2 回回して digest が **20/20 一致**

## 2. 時計の数字（作業環境・2 コア・2 並列）

  評価と記録で帯が違うので差（約 4%）を記録の費用とは言い切れないが、内訳でも記録の書き出しは見えない（§3）

## 3. 内訳（callgrind・命令数・1 局ずつ）

champion（評価 1 局 697 億命令／記録 1 局 620 億命令）。数字は「その関数とそこから呼んだもの全部」の割合:

- ネットの掛け算 `net::Dense::forward`: **82.0%**（評価）／**81.9%**（記録）。関数自体の命令が 81% で、ほぼ全部が素朴な掛け算と足し算の繰り返し
- そのうち代打ち π の経路（`Greedy::policy_pick` → `step_proxy`）: 74.8%／76.7%
- 根の対抗の読み（`clash_totals`）: 25.1%／22.2%（相手モデル π₀ と葉の V を含む。代打ちと重なって数えている）
- 観測の符号化 `encode::encode_state`: **7.1%**／7.1%
- 状態の更新 `engine::apply*`・合法手・決定化・束ねた解・世界の列挙: どれも 0.1% 前後（最適化で探索の関数に畳み込まれて見えにくいが、ネット以外の残り約 11% の中にある。文字列比較 5.5%・並べ替え数 %・メモリ確保 1% 程度が目立つ）
- Python と Rust の受け渡し: 対局列ごとに 1 回で、Python 側の起動と import を含めても 1% 未満
- 記録の書き出し: 上位に出てこない（0.1% 未満）

ネット無し（評価 1 局 10.5 億命令。うち半分は Python の起動と import で、対局の部分は 50.4%）:

- `engine::apply_owned`: 21.0%（対局の部分の約 42%）
- 状態の複製と破棄（`GameState::clone`・`drop_in_place`）: 約 8%（約 16%）
- 合法手の列挙 `legal_actions`: 約 5.6%（約 11%）
- メモリ確保と解放（`malloc`・`free` など）が自分の命令だけで約 21%（Python の起動分を含む）＝状態の複製が多い
- 符号化・ネットは無い

## 4. 言えることと言えないこと

言えること:
- **この構成のボトルネックはネットの推論で、特に探索の中の代打ち π である。**観測・符号化・受け渡しの高速化（C 化・バイナリ化）は、いまの構成では効きどころが無い
- ネットを使わない構成では、エンジンの状態更新と複製が主役になる

言えないこと:
- **命令数の割合は時間の割合そのものではない**（掛け算は 1 命令あたりが速い）。ただし時計でも、代打ち π を外すと 4.2 倍速になり、命令数の割合（約 75%）と整合している
- **マスターの PC の絶対値**（コア数と速さが違う）。必要なら同じ 2 本（約 20 分ずつ）を PC で回せる
- 汎用 AI の段階2 の教師がどれだけ遅いか（教師の構成がまだ決まっていない）

## 5. 汎用 AI の計画への申し送り

1. **段階2 の教師の費用は、探索の中で何回ネットを呼ぶかでほぼ決まる。**
   ネット無しなら 0.1 秒/局（1 万局で 2 コアなら約 8 分）、いまの champion 並みなら 11 秒/局（1 万局で 2 コアなら約 16 時間）。**2 桁違う**。
   教師の構成を決めるとき（段階2 の前）に、この数字で見積もる
2. SD001 専用のネットは他のデッキに使えない（計画書 §6 段階2）ので、横断教材の最初の教師は**ネット無しか、ネットの呼び出しが少ない構成**になる見込みが高い
3. 速くする必要が出たら、まず `net::Dense::forward`（いまは素朴なループ）の書き方か、代打ちの呼び出しの回数を見る。**高速化は一致を確かめる別の便に分ける**（計画書どおり）
4. ネット無しの構成を速くするなら、状態の複製（`clone`）とメモリ確保の削減が候補になる
