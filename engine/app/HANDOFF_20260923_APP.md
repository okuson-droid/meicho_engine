## 2. このチャットで決めたことと理由（本文は APP-015〜019）

- **マスターの指示（2026-09-22）「Active に出しただけだと読むのが面倒なので、私への依頼は必ずチャット上に出すこと」。**依頼はどこで・何を打つか・成功の見え方・確かめ方・引っかかりやすい所の 5 点と、「なぜいま」の 1 行を、毎回チャットに全文で書く。「前と同じ手順で」は禁止。マスターはコマンドプロンプトの手順を好む
- 揺れる検査は時間の判定ではなく**局の中身**が原因だった（シード 3079950380170938404 で再現）。検査は `FX_SEED` 固定で、止める条件を「7 ターン以上・ダメージ音・勝敗の音」にした。**止める条件は時間ではなく中身で書く**
- ダメージの出どころ（`src`）は、**その視点が見られるカードのときだけ**付ける（`visible_cards(prev[v])`）。量と与えた側は常に付ける。伏せ札の番号が漏れないようにするため
- ライフの差分は 0 で止める。エンジンはとどめでライフを負にしてから 0 に戻すので、差分をそのまま取ると偽の「回復」が出ていた
- 棋譜の送信の同意は**既定で送らない**。送り先がまだ無いので、設定の欄に「まだ送り先が無い」と注記するだけにした
- **デッキコードは自己完結の 8 字にはできない**（中身が最小でも約 120〜240 ビット、8 字の英数字は約 48 ビット）。マスター裁定「中身を詰める」で版 2 にした。SD001・SD02 は 24 字、無作為なデッキは 28〜44 字（中央値 39）。1 字の書き間違いはすべて拒む。版 1 の `MS1:` も読める
- `KNOWN_SETS` = ["SD01","SD02","BP01"] は**後ろに足すだけ**（並びが符号の一部。入れ替えると既存のコードが別のカードになる）
- リプレイは**サーバが記録を当て直して手の列を作り、画面は並べるだけ**。対局中と同じ `Game._advance` を通すので、出来事は対局中と一字一句同じ（検査で比べている）
- リプレイの視点は 4 つ: 席 0・席 1・観戦・全情報。**全情報は終局した対局だけ**（R-REP-3）。`build` が `not_finished` で断る。全情報でも山札の並びは出さない（観測に無い）
- 手元の記録の一覧とリプレイの HTTP 口（`GET /api/records`・`POST /api/records/replay`）は**手元起動だけ**（`_local_only`、CPU 対戦と同じ条件）。部屋のリプレイは WebSocket の `replay` で、部屋の全員（観戦者も）が受け取れる
- 版の違う記録（app_version・rules_version・cards_version）は、一覧に理由を出し、再生は断る（`old_record`）。エンジンが変わると当て直しの結果が変わりうるため

- **送り先が無いうちに、棋譜の送信の同意を初回に尋ねる画面** → 作らない。M7 の自動送信と一緒に
- **部屋の途中で表示名を変える** → 作らない。通信の変更が要る。表示名は次に入る部屋から効く
- **（撤回）タッチの直後の防ぎ（`lastTouch`）の初期値を 0 にする** → `-Infinity` に直した。0 だと読み込んでから 1 秒ホバーが効かなかった
