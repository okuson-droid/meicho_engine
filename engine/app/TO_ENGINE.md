## TE-13 不具合の報告: 【切り替え】が、切り替えに関わっていないキャラでも誘発する（2026-09-24・急ぎ度: 中・状態: 未）

マスターが知人との対戦で見つけた（「ショアキーパーのレベル 1 の切り替えスキルが、ショアキーパーが切り替えされていないときにも発動している」）。アプリ側で再現して、エンジンの挙動だと確かめた。アプリ側では直していない（`engine/meicho/` は持ち場の外）。

**再現。**SD001 対 SD02 の対局を進め、先攻のアクションフェイズで盤面を「リーダー BP01-018・バック 1 BP01-024・バック 2 **BP01-008**（ショアキーパー Lv1）」にして、`{"type": "switch", "back": 1}` を打つ。
切り替わったのはリーダーとバック 1 だけなのに、バック 2 の BP01-008 の【切り替え】（「カード1枚を引いてもよい。そうした場合、自分の手札1枚を捨てる。」）が `use_optional` として出る。

```

pending_choices [{'player': 0, 'kind': 'use_optional', 'card': 'BP01-008', 'skill_index': 0, 'ref': [0, 'chara', 'BP01-008', 0]}]
```

**原因の見当。**`_queue_fire_nested(s, Timing.SWITCHED, [owner])` の 3 か所（`engine.py` の行動としての切り替え・効果の切り替え・名指しの切り替え）が、`_active_skill_refs` でその席の**全部のキャラ枠**を拾っている。
rules_draft.md §7 の【切り替え】は「判定は既出の『◯◯』が切り替えされた場合と同じ（どちらの向きでも成立し、行われなかった場合は成立しない）」なので、**入れ替わった 2 枠（リーダーと、相手になったバック）**のキャラだけが誘発するはず、と読んだ。
3 か所とも入れ替えたバックの枠 `b` を知っているので、その 2 枠に絞れば足りそうに見える（重なった下のカードの【切り替え】を拾うかどうかは、§6.3-3 の扱いに合わせて判断してほしい）。

**欲しい結果。**直すかどうかの判断と、直したら `engine/TO_APP.md` で知らせてほしい（アプリは直ったエンジンをそのまま使うだけで、アプリ側の変更は要らない見込み）。rules の版と Rust の追従が要るかも判断を任せる。
再現の手順は上のとおりで、アプリの作業環境では `app.core.game.make_config` と `meicho.apply` だけで組んだ。
