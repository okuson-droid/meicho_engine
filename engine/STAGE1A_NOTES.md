# 段階1A報告 — 自動選択のPython実装便

更新日: 2026-09-14  
準拠: rules_draft v0.12 / engine v0.1 / encoding v4  
裁定: D-087 / 実施記録: D-088

## 0. 結論

段階1Aは完了した。従来は左端や名前順で自動決定していた戦略的な選択を、Pythonエンジンの
合法手として表に出した。対象は、協奏からのコスト支払い、公開領域間のカード移動、効果による
レベルアップ、準備時の3キャラの配置順である。

符号化はv4のままであり、新しい選択をまだ数値化できない。Rustと学習済みモデルも未変更である。
したがって次は、予定どおり段階1B「符号化v5・Rust・モデル移行便」である。

## 1. 対象範囲を決めた機械確認

- 準備配置: 3キャラのうちリーダーを固定しても、バック2枠には2通りの順序がある。切り替え行動は
  バック1と2を区別するため、これは異なる盤面である。合法手を3リーダー×2順序=6通りにした。
- 効果レベルアップ: 登録簿には同じキャラ・同じレベルの異なるカードが複数ある。たとえばアンコ、
  ショアキーパー、ツバキはLv1とLv2に各2候補ある。効果を持つ実装は6箇所あり、カードを名指ししない
  効果では同レベルと次レベルの両方が合法になりうる。よって選択肢化した。
- 同一IDの複数コピーは、どのコピーを選んでも結果が同じなので1つの合法手へ畳んだ。

## 2. 実装した選択

1. 協奏エリアから支払うカードを1枚ずつ選ぶ。
2. 効果の所有者が、相手の協奏からトラッシュへ送るカードを選ぶ。
3. 効果の所有者が、相手のトラッシュからデッキ下へ置くカードと0枚を含む終了時点を選ぶ。
4. 自分のトラッシュから手札へ回収するカードを選ぶ。
5. 自分のトラッシュから協奏へ置くカードを選ぶ。
6. 効果で重ねるキャラカードを選ぶ。同レベルと1つ上のレベルを基本ルールどおり候補にする。
7. 準備時にリーダー、バック1、バック2の並びを選ぶ。

条件付きの `levelup_by_effect_if_switched` と `trash_to_hand_if_switched` も、内部の旧左端処理へ
抜けず、同じ選択経路を通るようにした。

## 3. 互換性

- H、乱択、既存テストの既定回答は、従来と同じ左端・最大枚数・名前順を選ぶ。
- Python fingerprint 3種は不変:
  `773a71c15c5bc16e` / `677f28cc3b6995ee` / `6e39c2aa4b35d876`。
- 全決定列には新しい選択行動が現れるため、T-K-1のdigestはD-087後の値へ更新した。
- 対局記録の `APP_VERSION` を1から2へ上げた。v1記録を再生するときだけ、新設選択を旧既定回答で
  補う。新しいv2記録は選択行動をそのまま保存・再生する。
