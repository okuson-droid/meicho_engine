| 対戦相手 | 勝率 | 測定 |
|---|---|---|
| ヒューリスティック | **0.660 ±0.054** | n=300, 2026-08-23（公正化後） |

公正化による差は信頼区間内であり、**貪欲の優位は覗き見によるものではなかった**。
それでも修正が必要だったのは、この漏洩が探索の深さに比例して拡大する種類の

## 設計

各合法手を実際に `apply` して、結果の局面を評価関数で採点し、最大のものを選ぶ。

### 同時手番の扱い（決定化）

対抗ステップ (§6.4(1)) は同時提出のため、「自分の手を指した結果の局面」が
相手の手を仮定しないと定義できない。

1. 相手の手札を**未公開のカードから標本抽出**する（相手の手札は覗かない）
2. 標本ごとに相手の行動をヒューリスティック方策で決める
3. 標本を平均して各手の価値とする

標本数は6が最良だが、3でも12でも信頼区間内（0.647 / 0.675 / 0.652）。
**この近似は思ったより粗くて構わない**ということになる。

相手のデッキリストは既知として扱う（スターターデッキは公開情報）。
未指定なら自分と同じデッキと仮定する。

### 決定化は「先読みに入る前」に一度だけ通す（D-026, 2026-08-23）

決定化は相手の手札だけでは足りない。**デッキ順序も両者にとって隠蔽情報**であり、
素朴に `apply` すると先読み中のドローが実際の山札順で解決され、
「次に引く札を知った上で」手を比較することになる。`_determinize` は

1. 自分のデッキ: 中身は既知なので **`sorted` で正規化してから** シャッフル
2. 相手の手札とデッキ: 未公開カードをまとめて混ぜ、手札枚数分を配り直す

を行う。**正規化が要点である。** `shuffle` は入力の並びの関数なので、
実際の順序をそのまま混ぜると出力もまた実際の順序の関数になり、漏洩が消えない。
最初の修正案（`review_fair_greedy.py`）はここを踏み外しており、監査が
違反7件を残したままだった。

単独決定フェイズでは決定化した**1つの**局面の上で全候補を比較する。
候補ごとに決定化し直すと、引く札の当たり外れが候補の優劣に化ける。

### 評価関数

```
ライフ差 × 1.0 + 協奏差 × 0.8 + 手札差 × 0.5
+ 自分の使用可能な赤 × 0.4 + レベル差 × 0.0 + 残り資源差 × 0.05
```

参照するのは自分の全情報と、相手の**公開情報のみ**
（ライフ・手札枚数・協奏・トラッシュ・アクションエリア・キャラ・デッキ枚数）。
`test_greedy_does_not_peek_at_opponent_hand` で担保している。

## 最も重要な発見: 貪欲が効くフェイズと効かないフェイズは正反対

そのフェイズだけ貪欲にし、他はヒューリスティックに委ねて測った（各600局・±約0.040）。

| 貪欲にしたフェイズ | 対ヒューリスティック勝率 | |
|---|---|---|
| なし（対照） | 0.513 | 基準 |
| **対抗のみ** | **0.675** | 貪欲が明確に強い |
| 連撃のみ | 0.550 | やや強い |
| 選択のみ | 0.438 | 弱い |
| **アクションのみ** | **0.338** | 明確に弱い |
| 全部（純粋な貪欲） | 0.507 | 打ち消し合う |

**純粋な貪欲が対照とほぼ同じ（0.507）なのは、対抗での利得をアクションでの損失が
ちょうど打ち消していたため**である。フェイズごとに切り分けなければ見えなかった。

### なぜこうなるか

- **対抗ステップは1手先読みと相性が良い。** 利得がその場で確定し（ダメージ・ドロー・連撃）、
  かつ「相手の手を確率的に見積もる」という作業が規則では書きにくい。
  規則版は「自分の色を出す」の一手だったが、貪欲は手札の中身に応じて調整できる。
- **アクションフェイズは1手先読みと相性が悪い。** チャージ・レベルアップの価値は
  数ターン後に現れるのに、1手先の評価では**手札が1枚減った損失しか見えない**。
  ヒューリスティックの「協奏が4枚になるまでチャージする」という規則は、
  評価関数では表現できない長期方針だった。

これは「規則は長期方針を書ける、探索は局所最適を見つける」という一般論の実例になっている。
**既定構成は対抗＋連撃のみを貪欲にし、アクションと選択は規則に委ねる。**

## 評価関数の重み調整で分かったこと

### レベル差の項は害だった

| level の重み | 対ヒューリスティック勝率 |
|---|---|
| 1.0（当初） | 0.250 |
| **0.0** | **0.505** |
| 2.0 | 0.245 |

レベルアップは手札を消費するのに、1手先ではレベルが上がった事実しか見えない。
その結果、手札が薄いときにも上げてしまう。ヒューリスティック側は
「手札が5枚を超えているときだけ上げる」という条件で防いでいた。

### 重みの一つずつの掃引は誤導する

`hand=1.0` 単独 0.263、`concerto=0.4` 単独 0.343、`live_red=1.0` 単独 0.400 と
それぞれ改善して見えたが、**すべて組み合わせると 0.063 まで落ちた**。
`live_red` と `hand` はどちらも「カードを使うと下がる」項なので、
重ねると極端に消極的になり、対抗を35.7%もパスするようになる。

重みの調整は一つずつ動かすのではなく、組み合わせで探索する必要がある。
本メモの既定値は、フェイズを絞ったことで重みへの依存が小さくなった状態のものである。

## 既知の弱点・次にやること

1. ~~**アクションフェイズを貪欲にできていない。**~~ → **解決（2026-08-23）。**
   深さではなく**採点の地点**が問題だった。ターン内の行動列を単位として
   列挙し、対抗を解決したあとで採点すると 0.338 → 0.617 になる。
   `PLANNER_NOTES.md` / `meicho/planner.py` を参照。
2. **相手の行動モデルがヒューリスティック固定。** 相手が別の方策なら見積もりがずれる。
   IS-MCTSではここが再帰的に解かれる。
3. **評価関数は線形。** フェーズ4では価値ネットワークに置き換える前提で、
   本評価関数はその初期値・ロールアウト方策として再利用できる。
4. 速度は約25局/秒（クラウド実測。ヒューリスティックは約240局/秒）。
   大量実験には向かない。

## 再現

```python
from meicho.greedy import GreedyAgent
from meicho.runner import play_game
g = GreedyAgent(1, opp_decklist=DECK)      # 既定: 対抗+連撃のみ貪欲
r = play_game(config, [g, HeuristicAgent(2)], seed=42)
```

`phases={Phase.CLASH_SUBMIT}` のように渡すと担当フェイズを変えられる。
`Weights(...)` で評価の重みを差し替えられる。
