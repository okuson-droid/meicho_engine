## 0. 結論（先に）

### 0.1 一行で

**この試みは失敗した。ただし、失敗の理由がはっきり分かったので価値のある失敗である。
「勝敗を当てる能力」を上げても「強さ」は上がらなかった。**

### 0.2 何をやったか

現行のAI（計画探索）は、局面を採点する「評価関数」を持っている。中身は

```
点数 = ライフ差 ×1.0 ＋ 協奏差 ×1.034 ＋ 手札差 ×1.126
       ＋ 使える赤の枚数 ×0.533 ＋ レベル差 ×0.498 ＋ 資源差 ×0.061
```

という単純な足し算で、この倍率（**重み**と呼ぶ）は A-3 で**実際に対戦させて
勝率が上がるように**調整したものである。

今回やったのは、この重みを**自己対戦データから機械学習で決め直す**試みである。
4万局面ぶんの「この局面から、最終的にこの人が勝った／負けた」という記録を用意し、
それを一番よく言い当てる重みを計算した（**ロジスティック回帰**という手法。
詳細は §1 と `GLOSSARY.md`）。

### 0.3 結果

| | 勝敗の予測の当たり具合<br>（低いほど良い） | 対 H_default の勝率<br>（n=300） |
|---|---|---|
| **現行の評価関数**（勝率で調整した重み） | 0.5601 | **0.920 ±0.031** |
| 学習した重み（同じ6項目） | **0.5352**（良くなった） | 0.830 ±0.043 |
| 学習した重み（22項目に増やす） | **0.5241**（もっと良くなった） | 0.817 ±0.044 |

左の列は**対数損失**という指標で、勝敗の予測をどれだけ外したかを表す。
当てずっぽう（何を見ても「五分五分」と答える）が 0.693、完璧が 0 である。
学習した重みは 0.5601 → 0.5241 と下がっており、**予測は確かに上手くなった**。

右の列は実際に対戦させた勝率で、`±` の後ろは信頼区間
（＝測り直したときに収まるであろう範囲）である。
**0.920 ±0.031 と 0.830 ±0.043 は範囲が重ならない。つまり学習した重みの方が
はっきり弱い。** 偶然では説明しにくい差である。

現 champion（現行の計画探索）との直接対決も 0.460 ±0.056 と 0.447 ±0.056 で、
D-034 が定めた交代条件（勝率の 95% 下限が 0.5 を超えること）を満たさない。
**champion は交代しない。**

### 0.4 何が分かったか（ここが本題）

引継ぎ書は「CEM の到達点を超えないなら、**特徴が足りない**証拠になる」と
予想していた。ここでいう特徴とは「局面から取り出して見る項目」のことである。

**この予想は外れた。**

決め手は 2 行目の実験である。`logit6` は**現行とまったく同じ 6 項目**を使い、
倍率だけを学習で決め直したものである。項目が同じなのだから、
差は倍率の決め方からしか来ない。そしてそれが、**予測では勝ち、強さでは負けた**。

> **足りないのは見ている項目ではなく、「何を良くするように調整したか」である。**
>
> 現行の重みは「対戦して勝率が上がるように」決めた。
> 学習した重みは「勝敗を当てられるように」決めた。
> この2つは別物であり、後者を良くしても前者は良くならなかった。

理由の詳細は §3。ひとことで言えば、
**データから読み取れる「この局面は勝ちやすい」と、
探索が必要とする「そこへ動かすと得になる」は違う**からである。

## 1. 何と比べたか（予測の勝負）

### 1.1 現行の評価関数を「予測器」に仕立てる

学習モデルと現行の評価関数を比べたいが、そのままでは比べられない。
現行の評価関数が返すのは「+3.2 点」のような素点であって、勝率ではないからである。
一方の学習モデルは「勝率 0.73」を返す。単位が違うものは比較できない。

そこで**目盛りだけを合わせた**。素点を勝率に写す変換

```
勝率 = S字カーブ( 0.2326 × 素点 − 0.2844 )
```

の中の 2 つの数字（0.2326 と −0.2844）だけをデータから決めた。
**6 つの重みは A-3 で決めた値のまま一切動かしていない。**
これを `cem_calibrated` と呼び、「予測器として見たときの現行評価関数」とする。

（S字カーブはシグモイド関数といい、どんな実数も 0〜1 に押し込む関数である。
素点が大きいほど勝率が 1 に近づき、小さいほど 0 に近づく、という素直な変換をする。）

### 1.2 比べた 5 つ

| 名前 | 自由に決めた数字の個数 | 中身 |
|---|---|---|
| `const` | 0 | 何を見ても「五分五分」と答える。下限の基準 |
| `cem_calibrated` | 2 | 現行の重みのまま、目盛りだけ合わせたもの |
| `logit6` | 7 | **同じ 6 項目**で、重みも学習で決め直す |
| `logit22` | 23 | 22 項目に増やして学習 |
| `logit22x` | 28 | 22 項目＋「掛け合わせ」5 組を追加して学習 |

「掛け合わせ」（交互作用）とは、たとえば `ライフ差 × 協奏の枚数` のような項のことで、
「ライフ差の価値は協奏が厚いときとそうでないときで違うのではないか」という
引継ぎ書の仮説を、足し算だけのモデルで表現するための仕掛けである。

### 1.3 結果

| モデル | 予測の外し具合<br>（低いほど良い） | 正解率 | `cem_calibrated` との差 [95%範囲] |
|---|---|---|---|
| `const`（常に0.5） | 0.6931 | 0.500 | +0.1330 [+0.0982, +0.1684] |
| `cem_calibrated` | 0.5601 | 0.701 | —（基準） |
| `logit6` | 0.5352 | 0.717 | **−0.0250 [−0.0430, −0.0074]** |
| `logit22` | 0.5241 | 0.724 | **−0.0361 [−0.0544, −0.0198]** |
| `logit22x` | 0.5233 | 0.729 | −0.0368 [−0.0556, −0.0192] |

差の列はマイナスが「基準より良い」を意味する。角括弧は信頼区間で、
**範囲全体が 0 より小さければ「確かに良くなった」と言ってよい**。
`logit6` も `logit22` もそうなっているので、**学習した重みの方が予測は確かに上手い**。

### 1.4 この測り方で気をつけたこと（2 点）

**(1) データの行は互いに独立ではない。**
同じ対局から採った局面は当然よく似ている。さらに、同じターンの 2 行は
「自分から見た局面」と「相手から見た局面」であり、正解ラベルは必ず相補になる
（片方が勝ちなら、もう片方は負け）。こういうデータで教科書どおりに信頼区間を
計算すると、**範囲が狭く出すぎて、ありもしない差を「確かな差」と誤認する**。

対策として、区間は**対局を単位にした籤引きの繰り返し**（ブートストラップ、1000 回、
乱数の種は 20260824 に固定）で出した。局面ではなく対局ごと引き直すことで、
「同じ対局の局面は一蓮托生」という構造を保ったまま、ばらつきを直接測れる。

**(2) 正則化の強さも、答えを見ずに決めた。**
正則化とは重みが極端になるのを抑えるブレーキで、その強さを λ という数字で表す。
λ を valid（答え合わせ用データ）を見ながら選ぶと、valid が実質的に練習問題になり、
成績が甘く出る。そこで train の内部をさらに 5 つに分け（**これも対局単位で分ける**）、
train の中だけで λ を決めた。3 モデルとも λ = 10 が選ばれた。

### 1.5 派生してわかったこと 2 つ

**(a) 「掛け合わせ」は効かなかった。**
`logit22x` と `logit22` の差は −0.0007 [−0.0048, +0.0038]。
**範囲が 0 をまたいでいるので、差があるとは言えない。**
引継ぎ書 §1-3 の動機だった「ライフ差の価値は協奏の枚数に依存する」という仮説は、
少なくとも今回試した 5 組では**データに支持されなかった**。
これは後で「MLP に進むべきか」の判断材料になる（§4）。

**(b) 項目を 6 から 22 に増やしても、予測は有意には良くならなかった。**
`logit22` と `logit6` の差は −0.0111 [−0.0217, +0.0001]。
点としては改善しているが、範囲が辛うじて 0 をまたぐ。

理由の一端は、22 項目の中に**数式的な重複**があることである。たとえば

```
ライフ差 = 自分のライフ − 相手のライフ
```

なので、この 3 つを同時に入れても情報は増えない。実際、22 項目＋定数項の 23 列のうち、
独立な情報は **17 本しかない**（残る 6 本は他から計算できてしまう）。
**足し算だけのモデルにとって、素の値は差分の情報を 1 ビットも増やさない。**
素の値を入れた意図（「ライフ差 5 の意味は 18対13 と 6対1 で違うはず」）が
活きるとすれば非線形なモデルにおいてだが、その非線形性の余地が薄いことは (a) が示している。

## 2. 強さの測定（本番の勝負）

予測が上手くなったので、次は「実際に強くなったか」を対戦で確かめる。

シード帯 **110000..** を使った。これは**学習にも λ の選択にも一度も使っていない**
番号の範囲で、台帳（`experiments/seed_bands.json`）に登録済みである。
調整に使った番号で成績も測ると「その番号に都合よく合わせただけ」の成績が出るため、
このプロジェクトでは帯を必ず分ける（D-028）。
また対戦はシードの偶奇で先攻後攻を入れ替えるので、先攻有利は相殺される。

| 対戦 | 勝率 (n=300) |
|---|---|
| 学習22項目 vs H_default | 0.817 ±0.044 |
| 学習6項目 vs H_default | 0.830 ±0.043 |
| **現行 planner vs H_default** | **0.920 ±0.031** |
| 学習22項目 vs 現行 planner | 0.460 ±0.056 |
| 学習6項目 vs 現行 planner | 0.447 ±0.056 |

対 H で見ると、現行 0.920 ±0.031（範囲 0.889〜0.951）と
学習 0.830 ±0.043（範囲 0.787〜0.873）は**重ならない**。
つまり**学習した重みの方がはっきり弱い**。

なお、差し替えたのは**葉の採点だけ**である（`GreedyAgent._eval`）。
探索の構造も、見えない情報の扱い方（決定化）も、乱数の使い方も現行のままにした。
したがってこれは「採点の質だけを入れ替えた対照実験」になっており、
差の原因を採点に帰せる。

## 3. なぜ効かないのか（診断）

ここが本文書の中心である。B-3（相手モデルの負の結果、`B3_NOTES.md` / D-032）が
「効かなかった」で止めずに理由まで突き止めた前例にならい、機構を特定した。

道具は `experiments/diag_valuenet.py`。実対局 8 局を走らせ、計画探索が
「どの手を選ぶか」を決めるたびに、比較対象となった候補局面を全部記録する
（564 回の決定、候補局面 19,504 件）。

### 3.1 まず、外れていた仮説を 3 つ潰した

**仮説A「飽和」——勝勢や敗勢では、どの候補も同じ点数に潰れてしまうのではないか。**

学習モデルは勝率を返すので、圧勝の局面ではどの候補も「99% 勝ち」になり、
候補どうしの差が消えてしまうのではないか、という懸念である。
現行の評価関数はライフ差にそのまま比例するので、圧勝でも「もっと圧勝」を目指せる。

→ **否定された。** 決定ごとの候補のばらつきを、局面の有利さの度合いで分けて調べたが、
互角の局面でも圧勝の局面でもばらつきの相対量は変わらなかった（0.963 と 1.036）。

**仮説B「凍結した項目」——1 回の決定の中で値が動かない項目に重みを取られている。**

たとえば「これまでに相手がパスした回数」は、1 回の決定の中では全候補で同じ値である。
そういう項目にどれだけ重みを付けても、どの手を選ぶかには一切影響しない。
つまり「予測には効くが選択には効かない」重みが混ざっている可能性。

→ **影響は小さかった。** 決定内でほとんど動かない項目は `turn_no` と
`clash_pass_diff` の 2 つだけで、学習モデルの重み全体の **7.3%** にすぎない。

**仮説C「重複による重みの割り振りの不定性」——数式的に重複した項目のせいで、
重みの配り方が偶然で決まり、それが順位付けを狂わせている。**

§1.5(b) で述べた重複（`ライフ差 = 自分のライフ − 相手のライフ`）があると、
予測の精度は同じでも重みの配分は無数にありうる。その配分の違いが、
候補どうしの比較では効いてしまうのではないか、という筋である。

→ **否定された。** 重複を含まない 6 項目版（`logit6`）で測り直しても、
同じように弱かった（対 H 0.830）。

### 3.2 残った機構: 「良くしようとしたもの」が違う

**回帰が当てているのは「その局面にいる人が勝つ確率」である。
探索が必要としているのは「そこへ動かすと得になるか」である。**

この 2 つは、ある項目が結果と相関する理由が「その項目自体の働き」以外にもあるとき、
必ずずれる。統計でいう**相関と因果の違い**であり、このゲームでは次のように現れる。

現行 6 項目の重みを、ライフ差を 1.0 に揃えて並べると:

| 項目 | 現行（対戦の勝率で調整） | 学習（勝敗の予測で調整） | 差の向き |
|---|---|---|---|
| ライフ差 | 1.000 | 1.000 | — |
| 協奏差 | 1.034 | 1.713 | 予測は 1.7 倍重く見る |
| 手札差 | 1.126 | 1.403 | 予測は 1.2 倍重く見る |
| 使える赤の枚数 | 0.533 | 0.166 | 予測は **3 分の 1** |
| キャラのレベル差 | +0.498 | **−0.197** | **プラスとマイナスが逆転** |

**レベル差の符号反転が、この現象のいちばん分かりやすい例である。**

レベルアップは手札を払って行う行動である。したがってデータの中では、
「キャラのレベルが高い局面」は「たった今、手札を減らした直後の局面」と重なる。
手札が少ない局面は勝ちにくい。だから回帰は素直に
**「レベルが高いことは悪いことだ」と学ぶ**（重み −0.197）。

しかしこれは因果を取り違えている。
**「レベルが高い局面が負けやすい」ことと「レベルアップすると負けやすくなる」ことは、
まったく別の主張である。**

> **【2026-08-24 追記・訂正】** 本稿は当初ここで「A-3 の +0.498 が正しく、
> レベルアップにはやる価値がある」と書いていた。**その部分は言い過ぎだったので訂正する。**
> D-039 で対照実験（同じ局面から「やる枝」と「やらない枝」を両方走らせる）を
> 行ったところ、**レベルアップの勝率への実際の効果はおよそ 0** だった
> （相手が計画探索のとき +0.000 [−0.090, +0.085]、n=200）。
> A-3 の +0.498 は「他の 5 つの重みと組み合わせたときに強くなる値」であって、
> 行動の価値を単独で意味する数字ではない。
> **ただし、真の効果が 0 である以上、回帰が −0.197 を付けたことは
> やはり関連を効果と読み違えた結果である**（0 でないものを付けている）。
> また本文書の主結論（予測を良くしても強くならない）は、この例に依存しない
> 独立した測定（§0.3・§2）に立っているため揺らがない。
> 詳細は `ACTION_VALUE_NOTES.md` / D-039。

しかも**このプロジェクトは既に一度この罠を踏んでいる**。
`GREEDY_NOTES.md` に記録があるとおり、1 手先しか読まない貪欲エージェントでは
レベルアップが「手札が減っただけ」に見えるため、`Weights.level` の既定値は 0.0 である。
ターン全体を見通せる計画探索になって初めて +0.498 が正しくなった。
**回帰は、貪欲と同じ罠に、より洗練された形で落ちている。**

### 3.3 補強となる 2 つの観察

**(1) 決定を動かす力の配分が違う。**

1 回の決定の中で、ある項目がどれだけ選択を左右するかは
「重み × その決定の中でのその項目のばらつき」で測れる。
これを全項目について足し合わせて内訳を見ると:

- 現行の評価関数は、**決定を動かす力の 85% を 3 項目**（ライフ・手札・協奏）に
  集中させている。これらは行動によって実際に動く項目である。
- 学習モデルは 15 項目に薄く広げており、ライフ差の取り分は **41% → 19%** に落ちる。

予測の精度を稼ぐために重みを分散させた結果、
**「行動が動かせる項目」への集中が薄まっている**。

**(2) 大筋では同意しているのに、選ぶ手は 4 割食い違う。**

現行の評価関数と学習モデルで、候補局面の順位付けがどれだけ一致するかを測ると、
順位相関は中央値 0.902 と高い（1.0 が完全一致）。ところが
**「最良の候補」が一致した決定は 59.0% にとどまる**。
全体の並びはよく似ているのに、頂点だけが 4 割で入れ替わる。
探索が使うのは頂点だけなので、この 4 割が負けにつながっている。

## 4. 次にやるべきこと（§4.1-3 への申し送り）

### 4.1 当初の計画（MLP）は勧めない

引継ぎ書の当初案は、次の段階で **MLP** を試すことだった。
MLP とは、足し算だけのモデルを何段も重ねて間に「曲げる」処理を挟んだもので、
項目どうしの複雑な絡み合いを自動で見つけられる仕組みである
（いわゆるニューラルネットワークの最も基本的な形）。

**しかし、同じやり方のまま MLP に進むことは勧めない。** 根拠が 3 つある。

1. **絡み合いを足しても予測が良くならなかった**（§1.5-a）。
   MLP の売りは絡み合いを表現できることだが、その絡み合いに旨味が無いことが
   安価な先行検査で分かってしまった。
2. **予測が良くなっても強さに翻訳されないことが、対照実験で示された**（§0.4）。
   モデルの表現力を上げても、翻訳されない量がより精密になるだけである。
3. **項目を 6 から 22 に増やしても予測すら有意に良くならなかった**（§1.5-b）。

要するに、伸びしろがあるはずの 3 つの方向すべてで、伸びしろが確認できていない。

### 4.2 代わりに勧める 2 案

**(a) 勝率で直接調整する（推奨。安く、既存の資産が使える）**

A-3 で使った `experiments/optimize_cem.py` を、6 項目から 22 項目に拡張する。
CEM は「実際に対戦させて勝率が高かった重みの周辺を探す」やり方なので、
§3.2 で問題になったずれが**原理的に起きない**。良くしようとしているものが
最初から「強さ」だからである。

必要な部品はすでに揃っている。特徴抽出（`meicho/features.py`）も、
重みを差し替えて動かす仕組み（`meicho/valuenet.py`）も、
今回作ったものがそのまま使える。速度の制約も無いことは D-035 で確認済みである。

懸念は探索の重さで、22 個の重みは 6 個より探しにくい。
A-3 は 8 世代 × 個体 12 × 各 30 局で 6 個を調整した。同じ密度なら
22 個には数倍の対戦数が要る。**時間の見積もりを先に取るべきである。**

**(b) 「良くしようとするもの」を順位付けに合わせる（大きい工事）**

探索が実際に比べているのは「同じ決定の中の候補どうし」である。
ならば学習も「どちらの候補が良いか」を当てる形にすればよい
（候補の対を作って順位を学習させる）。あるいは、生の勝敗ではなく
**探索自身が出した評価**を教師にする形もある（囲碁・将棋のAIで使われる作り）。

こちらは筋が良いが、データの作り直しと学習の枠組みの作り直しが要る。
(a) を先に試して、それでも頭打ちなら着手するのが順当である。

### 4.3 全体に効く裁定

**「予測が良くなった」を強さの代理指標にしてはならない。**
D-038 以降、価値関数の採否はラダー（実際の総当たり戦。D-034）でのみ判断する。
## 5. 作ったもの

- `meicho/features.py` — 特徴抽出（D-037 で `experiments/` から昇格して移動）
- `meicho/valuenet.py` — `LinearValue` / `ValuePlannerAgent` / `ValueMCTSAgent`。
  差し替えているのは `GreedyAgent._eval`（と MCTS の `_leaf01`）だけ
- `GreedyAgent._eval` / `MCTSAgent._leaf01` — 葉評価の差し替え口。
  導入時に fingerprint 3種が不変であることを確認済み
- `experiments/train_linear.py` — 学習と比較（IRLS・対局単位CV・対局単位ブートストラップ）
- `experiments/measure_valuenet.py` — 強さの測定（帯 110000..）
- `experiments/diag_valuenet.py` — 診断
- `results/models/c1_{linear_v1,logit6,logit22,logit22x}.json`
- registry に `planner_v` / `mcts_v` を登録（学習済みモデルは kwargs の `model` で渡す）
- テスト 8 件追加（`tests/test_valuenet.py`）: 学習時と推論時の値の一致・終端の ±WIN・
  MCTS の葉が [0,1]・**覗き見監査**・決定性・差し替えが効いていることの確認

## 6. 再現

```
python3 experiments/train_linear.py                        # 学習と予測の比較（3秒）
python3 experiments/measure_valuenet.py 300 --workers 2    # 強さ（約6分）

python3 experiments/diag_valuenet.py 8                     # 診断（約1分）
```
