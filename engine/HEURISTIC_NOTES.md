作成: 2026-08-22 / 実装: `meicho/heuristic.py` / 準拠: rules_draft.md v0.10

## 位置づけ

フェーズ3（ヒューリスティック/貪欲エージェント → マッチアップ勝率行列）の第一弾。
規則ベースで全フェイズの方策を持ち、調整パラメータを `Params` に外出ししてある。

## 強さ（SD001同型・2000局・先攻後攻を入れ替えた両方向）

| 対戦相手 | 勝率 | 平均ターン |
|---|---|---:|
| ランダム | **0.980 ±0.006** | 15.9 |
| 調整前の版 | 0.590 ±0.022 | 15.7 |
| ランダム同士（対照） | 0.500 ±0.028 | 31.9 |

対局が半分の長さで終わっている（31.9 → 15.9ターン）。押し切っている。

**制約の担保**: 相手の手札・デッキ順序を参照していないことを
`test_heuristic_does_not_peek_at_opponent_hand` で検査している。
隠蔽情報を差し替えても選択が変わらないことを確認する形で、
「強い」のではなく「カンニングしている」状態を防いでいる。

## A-4 規則の整理（2026-08-23・レビュー §6 A-4 / §3.5）

引継ぎ書のアブレーションは **SD001 同型の自己対戦のみ**だった。レビュー §3.5 の
「同型対戦の相対寄与は絶対値を強調しうる」という指摘に従い、3条件で測り直した。
再現: `python3 experiments/ablation.py 600 200 2`

表の数字は**規則を無効にした版の勝率**。0.5 を明確に下回れば規則が効いている。

| 無効にした規則 | 同型戦 (n=600) | 異型戦 SD001vsSD02 (n=600) | 計画探索の中で (n=200) |
|---|---|---|---|
| **協奏エリアの整備** | **0.090 ±0.023** | **0.140 ±0.028** | 0.475 ±0.069 |
| レベルアップ | 0.435 ±0.040 | 0.487 ±0.040 | 0.495 ±0.069 |
| 赤を生き返らせる切り替え | 0.410 ±0.039 | 0.427 ±0.040 | 0.485 ±0.069 |
| 捨て札を価値で選ぶ | 0.413 ±0.039 | 0.422 ±0.040 | 0.525 ±0.069 |
| **対抗の色の混合** | 0.403 ±0.039 | 0.452 ±0.040 | **0.360 ±0.067** |
| ~~リーサル確定~~ | 0.492 ±0.040 | 0.498 ±0.040 | 0.475 ±0.069 |
| ~~連撃中の変奏コンボ~~ | 0.508 ±0.040 | 0.505 ±0.040 | 0.485 ±0.069 |
| ~~出せないなら対抗しない~~ | 0.503 ±0.040 | 0.508 ±0.040 | 0.480 ±0.069 |

### 3条件とも寄与ゼロだった3規則は削除した

取り消し線の3つはどの条件でも信頼区間が 0.5 を含む。`heuristic.py` から
規則本体・`use_*` フラグ・`variation_min_unlock` ごと削除した。
削除後も **H vs ランダム 0.975 ±0.012**（n=600）で強さは変わっていない。

- **リーサル確定**: 規則としては書けない種類の判断だった。`ダメージ ≥ 相手ライフ`
  で判定していたが、**対抗に勝たなければダメージは入らない**（§6.4(2)-4）ので
  確定ではない。「対抗に勝つ見込み」の見積もりが要る。これは決定化して数える側の
  仕事であり、`greedy`/`planner` の評価関数は勝利を WIN=10000 として直接見ている。
  **正しい分担に戻した**というのが実態である。
- **連撃中の変奏コンボ**: 解放の価値は連撃が続くかどうかに依存し、閾値では表せない。
  CFRレポート追補5の「変奏コンボは判定不能」という負の結果と整合する。
- **出せないなら対抗しない**: 発火条件（手札の**全部**が使用不能）が稀すぎた。
  規則が間違っていたのではなく、効果が出るほど発火しない。

### 条件を変えたら判定が変わった2件（§3.5 の指摘は正しかった）

- **レベルアップ**: 同型戦 0.435（効く）→ 異型戦 0.487・計画探索の中 0.495（差なし）。
  **同型戦の相対寄与が絶対値を強調していた**典型例。削除はしないが、
  「効く規則」として引用するときは条件を添えること。
- **対抗の色の混合**: 旧測定では 0.508（差なし）だったが、今回は3条件とも効いた。
  しかも**計画探索の中でいちばん効く規則**（0.360）である。
  旧測定の条件は再現できないが、`own_color_weight` の掃引（0.0 で 0.445）と
  矛盾していたので、今回の値を採る。

### 規則の寄与は「単体の強さ」と「探索の部品としての価値」で別物

**協奏エリアの整備は単体では圧倒的（0.090）なのに、計画探索の中では差がない（0.475）。**
ターン計画探索はチャージの価値を自力で見つけるので、ロールアウト方策が
チャージしなくても結論が変わらない。逆に**対抗の色の混合は探索の中でこそ効く**
（0.360）。対抗は計画探索の終端で固定方策が解決する部分だからである。

ヒューリスティックは今や (a) ベンチマークの相手、(b) 探索のロールアウト方策、
(c) 相手モデル、の3役を兼ねている。**規則を評価するときは用途を指定すること。**

## 最大の発見: 3すくみで相手の色を踏むのは逆効果

CFR実験（experiments/CLASH_CFR_REPORT.md）の主結果は
「相手のリーダーの担当色を3すくみで踏む」だった。しかし実ゲームで測ると**逆だった**。

**パラメータ掃引（各2000局・vs 既定版）**

| counter_weight（相手の色を踏む重み） | 勝率 |
|---|---|
| 0.0 | **0.531 ±0.026**（最も強い） |
| 1.0 | 0.507 |
| 3.0 | 既定（基準） |
| 6.0 | 0.473 |
| 12.0 | 0.468 |

| own_color_weight（自分の担当色の重み） | 勝率 |
|---|---|
| 0.0 | 0.445（明確に弱い） |
| 1.5 | 0.528 |
| 5.0 | 0.563 |
| 15.0 | 0.591 |
| 1000.0（ほぼ確定） | 0.599 |

**搾取されるかの検証（各2000局）**

| 対戦 | 勝率 |
|---|---|
| 自色確定 vs カウンター確定 | **0.657 ±0.021**（自色確定の勝ち） |
| 自色確定 vs 混合 | 0.544 ±0.022 |
| 混合 vs カウンター確定 | 0.615 ±0.021 |

**自色を出し続ける方策は、狙って踏みに来る相手にすら勝つ。**

### なぜCFRの結論と逆になったか

CFR実験の追補1で測った「1手番モデルは手札の枯渇を無視している」がそのまま効いている。

- **カウンターは自分のLv0ボーナスを捨てる行為である。** キャラのLv0は
  **勝敗を問わず**担当色を出せば発動する（§6.4(1)-4）。踏みに行くと毎回これを失う。
- **カウンター色は希少なことが多い。** 相手が熾霞（赤）なら青で踏むことになるが、
  青はデッキに9枚しかない。追撃1の対抗に勝つために、続かない資源を燃やしている。
- CFRは1回の対抗の利得しか見ておらず、この機会費用を評価していなかった。

つまりCFRの結論が誤りだったのではなく、**CFRが解いていた部分ゲームが実ゲームと
違っていた**。追補1で予告した「青緑を5ポイント程度過大評価している」という
限界が、実測で桁違いに大きかったということになる。

### 既定値を12.0に留めた理由（と、A-5 でそれを測った結果）

`own_color_weight` は大きいほど強く、単調に改善する（1000.0で0.599）。
しかし確定方策は原理的に読まれうる。ここで対戦した「カウンター確定」は
固定方策であって適応的な相手ではない。IS-MCTS等の適応的な相手には
搾取されうるため、自色を約8割に留めて不確実性を残している。
勝率差は 12.0 と 1000.0 で信頼区間内に収まっており、実測上の損失はない。

## A-5 被搾取性の測定（2026-08-23・レビュー §6 A-5 / 引継ぎ書 §7.2）

上の「保険」に値段が付いていなかったので測った。凍結した相手 π に対する
**最適応答の到達勝率 BR(π)** を被搾取性の実測下界とし、混合の度合いだけが違う
π を並べて BR の差を見る。再現: `python3 experiments/exploitability.py 6 10 40 2`

- π_det = H(own_color_weight=1000) 自色ほぼ確定
- π_def = H(own_color_weight=12) 既定（自色 約8割）
- π_mix = H(own_color_weight=1.5) よく混ぜる

### 段階1: 素朴な搾取（counter_weight 掃引・n=600・探索側もヒューリスティック）

| 探索側 counter_weight | vs π_det | vs π_def | vs π_mix |
|---|---|---|---|
| **0.0** | **0.462** | **0.490** | **0.563** |
| 3.0 | 0.427 | 0.463 | 0.528 |
| 6.0 | 0.423 | 0.462 | 0.498 |
| 12.0 | 0.387 | 0.417 | 0.488 |
| 30.0 | 0.390 | 0.412 | 0.480 |

**「相手の色が読めるなら踏めばよい」は成立しない。** 相手がほぼ確定で自色を
出してくると分かっていてなお、3すくみで踏みに行くほど弱くなる。
自色確定の相手に対してすら最良は counter_weight=0 だった。
理由は既出の機構そのままである。踏みに行くと自分のLv0ボーナス（勝敗を問わず発動）を
毎回捨て、しかも希少な青緑を燃やすことになる。**相手の色を当てても割に合わない。**

### 段階2: CEM による最適応答（π ごとに13次元を個別最適化）

探索はシード帯 0..、検証は**未使用のシード帯 20000..**（D-028 の規約）。

| 凍結した相手 | 最適応答 BR(π) | 対照: 既定の計画探索 |
|---|---|---|
| π_det（自色ほぼ確定） | **0.850 ±0.040** | 0.847 ±0.041 |
| π_def（既定・自色8割） | **0.873 ±0.038** | 0.850 ±0.040 |
| π_mix（よく混ぜる） | **0.890 ±0.035** | 0.877 ±0.037 |

**BR(π_det) − BR(π_def) = −0.023。確定にする代償は測れなかった。**
むしろ順序は一貫して「混ぜるほど搾取されやすい」（0.850 < 0.873 < 0.890）で、
段階1と段階2で同じ向きに出ている。差はいずれも信頼区間内だが、
**「混ぜたほうが安全」を支持する証拠は一つも出なかった。**

副次的な確認: π ごとに個別最適化した BR は、汎用の調整済み計画探索より
+0.003 / +0.023 / +0.013 しか上回らない。**調整済みの計画探索は既に
このヒューリスティック族への近似最適応答になっている。**
BR のパラメータベクトルは π ごとに大きく違うのに勝率がほぼ同じで、
これは A-4 で見つけた「13次元のうち10次元は平坦」と整合する。

### この測定が答えていないこと（重要）

得られたのは**下界**である。最適応答の探索クラスは
「静的なパラメータベクトル」に限られており、**対戦中に相手の傾向を学ぶ相手**は
含まれていない。「BR(π_det) が上がらなかった」は「搾取されない」の証明ではなく、
**「この探索能力では搾取できない」**という意味にとどまる。
人間や履歴を持つ IS-MCTS（レビュー §6 B-3）はこの外側にいる。

### 判断: 既定は 12.0 のまま据え置く

保険料は測ったが、**保険が要るという証拠も、保険が無駄だという証拠も出なかった**
（差はすべて信頼区間内）。実測上の損失がない以上、適応的な相手への保険として
12.0 を維持する。この判断を見直す条件は明確で、**B-3（履歴特徴・相手モデルの
脱固定化）を実装して、適応的な相手を BR の探索クラスに入れてから**である。

## 既知の弱点・次にやること

1. **対抗ステップが実質「自分の色を出す」だけになっている。**
   相手の手札推測も、温存も、駆け引きもない。ここはIS-MCTS/CFRの領分。
2. **リーサル判定が機能していない。** 対抗に勝つ見込みを考慮していないため。
   「相手が出せる色の分布」を考えないと正しく書けない。
3. **貪欲エージェント（1手先読み＋評価関数）が未実装。**
   本エージェントとの比較で評価関数の質を測れる。
4. **マッチアップ勝率行列は現状2デッキ×1エージェント。**
   SD001 vs SD02（両者ヒューリスティック）は **0.500 ±0.022** で完全に互角だった。
   ブースター発売後にデッキが増えたら本格化する。

## 再現

```python
from meicho.heuristic import HeuristicAgent, Params
from meicho.runner import play_game
r = play_game(config, [HeuristicAgent(1), HeuristicAgent(2)], seed=42)
```

パラメータを変えるときは `HeuristicAgent(seed, Params(concerto_target=3))` のように渡す。
`Params` の `use_*` フラグを False にすると個別の規則を無効化でき、寄与を切り分けられる。
