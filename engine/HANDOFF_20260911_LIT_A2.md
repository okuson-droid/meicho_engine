## §0 結論（先に）

### 0.1 何をするか

**対抗の集約規則を 1 つだけ変える**——決定化 K 本の**それぞれ**で相手の最尤 1 手を当てて
期待値を取る現行方式に代えて、**AI の提出分布 x を K 本に共通に置いたまま**
`max_x Σ_k w_k min_{y_k} xᵀA_k y_k` を RM+ で解き、**平均戦略**から手を選ぶ。

新しいつまみ **`bundle_p`**（既定 `0.0` ＝ 無効）を Python と Rust に足す。
`p` は「現行の評価（π₀ の最尤 1 手）」と「束ねた最悪想定」の混ぜ方である:

```
A_k[i][j] = p · （現行どおり π₀ の最尤 1 手に対する値）
          + (1−p) · （相手の手 j に対する値）
```

- **`bundle_p = 1.0` は現行 champion と 1 手・1 点まで同じでなければならない**（検査 T-A2-2）。
  行列の全列が同じ値になり、どんな x も同じ値を返すので、RM+ は現行の最良手に収束する。
- **`p = 0`（純粋な最悪想定）は候補にしない**（計画書 §3.1 の転びやすいところ (1)。
  A-9 の δ=0 で「相手を強く見積もりすぎて詰みを逃す」が実測されている）。
- 候補は **p ∈ {0.9, 0.75, 0.5}**（計画書 §3.1 手順 3 の指定どおり）。

**この便で変える探索器の要素は「対抗の集約規則」の 1 つだけ**である。
世界の作り方（`known_hand` / `endgame_enum` / `draw_buckets`）・葉の V・π₀・代打ちは触らない。

## §1 守ること（便固有のぶんだけ。共通は `HANDOFF_CONVENTIONS.md`）

- **Python が真実源・Rust は写し。** ソルバは反復法なので、**足し算の順序まで揃える**こと。
  浮動小数の順序が違うと平均戦略が 1e-12 ずれ、同点の手の選び方が変わって**手が割れる**。
  毎手一致の検査は手だけでなく**点数まで**（`rel=1e-6`）。
- **平均戦略を返す。** RM+ のその時々の戦略は角に寄る。ここを取り違えると全部が嘘になる
  （便 D の T-L5 で同じ罠を一度踏みかけている）。**わざと最終反復を返すように壊して、
  検査が落ちることを確かめる。**
- **乱数を消費しない。** RM+ は決定的に回す（初期値は一様・反復数は固定）。
  つまみ 0 のときはもちろん、**つまみ 1 のときも新たに乱数を引かない**設計にする。
  引いてしまうと以降の引きが全部ずれ、候補間の同シード比較が壊れる。
- **覗き見禁止（D-026）。** 行列を埋めるのに使ってよいのは `_worlds` が返した世界だけ。
  `s.peeked_opp_hand` にも相手の真の手札にも触れない。候補は必ず覗き見監査を通す。
- **`experiments/vb.py`・`cards/`・`decklists/`・`experiments/champion.py`・
  `gauntlets/*.json`・`webapp/` の既定は触らない**（交代が決まるまで）。
  `webapp/agents.py` に**選べる相手を 1 行足すのは可**。
- **ファイルは消さない。`.bin` は持ち帰らない。Linux の wheel は PC に戻さない。**

## §7 転びやすいところ（症状 → 意味 → 直し方）

1. **`bundle_p=1.0` が現行と 1 手だけ違う。**
   → 行列の全列が同値なのに、同点の割り方が違う（RM+ の平均戦略が一様に近い値を返し、
   `argmax` の同点処理が現行と別の手を拾っている）。
   → **同点のときは「行列の行の順＝合法手の順で最初」を選ぶ**と決め、現行の `_clash` と揃える。

2. **候補間の同シード比較がずれる。**
   → ソルバが乱数を引いている（T-A2-6 が無いと気づけない）。
   → 初期値を一様に固定し、反復を決定的にする。**`rng` を渡さない。**

3. **Python と Rust で手が割れるが、点数は 1e-12 しか違わない。**
   → 足し算の順序（K 本の重み付き和の取り方）が違う。
   → **k の順序と、行列の走査順を Python に完全に合わせる。** 累積の型も揃える。

4. **終盤だけ極端に遅い。**
   → `endgame_enum` が 64 本列挙し、行列が 9×9×64 になっている（§0.3 (iii) の想定どおり）。
   → まず**測る**。落とすなら「列挙が発火した決定では束ねを使わない」ではなく
   **反復数を下げる**ほうを先に検討する（特別扱いを増やさない）。

5. **`PlannerAgent(**champion.kwargs_for("SD001"))` が `ValueError` で落ちる。**
   → 新 champion は `endgame_enum` を持つので `opp_decklist` が要る。仕様である。
   → `opp_decklist=pool` を一緒に渡す。`registry.make` 経由なら不要。

6. **検査が思わぬところでまとめて落ちる。**
   → 便 C のつまみを「既定オフ」として測る検査は、**土台を
   `champion.kwargs_for` から取っている**（`tests/test_lit_c.py::_champ_kw` が便 C のつまみを外す形）。
   `bundle_p` を champion に入れるとき（＝交代のとき）は、**`_BIN_C_KNOBS` と同じ扱いの一覧に
   `bundle_p` を足す**。
   → **読み替えて直す。検査を消さない。**

7. **`ladder.py` の「champion 候補」欄と条文が食い違って見える。**
   → あれはラダー内の n=300 の簡易判定で、D-081 の第 1 条件（**別帯**の n≥300）とは別物。
   → 食い違いは隠さず報告に書く。

8. **`bash` の 600 秒上限。**
   → 長い測定は `--budget-sec 480` と `--resume` で分割し、**前面で塊にして**回す（裏回しは消える）。
