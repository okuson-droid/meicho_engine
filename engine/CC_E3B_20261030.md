### 0.2 主比較（M-1・M-2・M-3）

- 道具: `eval_s3_h2h.py run --pair e3b=<V_0>+bundle_p=0.5:<V_0>+bundle_p=0.75`。調整デッキ 16 ブロック × 176 局＝2,816 局。帯は 989200..989375
  - 1 ブロックの局数は偶数にする（M-8・M-1 の 2,800 より優先）
- null: `--pair null=<V_0>+bundle_p=0.75:<V_0>+bundle_p=0.75`（netfree_vb どうし）。16 × 26＝416 局で、配線の確かめに使う。帯は 989400..989425
- 判定は直接の得点（挑戦の A 席の得点 − 0.5）の 95% 区間で読む（局の組 (2k, 2k+1) をブロックの中で再標本化する）。言葉は M-2 の 4 つ
  - E-3a・E-1・E-2 と家族にしない（D-181 §3）ので、水準は 95% である
- 二段構え（M-3）
  - 足し継ぎ（探索）から出せるのは「否定」「悪くなった」「候補」の 3 つだけである
  - 「区別できない（上端は否定できない）」なら、同じ大きさ（16 × 176）の新しい帯を回す前に登録して足し継ぐ
  - 上限は 3 回（M-4・8,448 局）
  - 合わせた区間の下端 > 0 は「候補」であって「伸びた」ではない
  - 「伸びた」は、新しい帯での 1 回だけの確かめからしか出さない。局数は探索の点推定を検出力 80%・95%・1 局の標準偏差 0.49 で見つける大きさから逆算し、1 ブロックを偶数に切り上げる（最低 2,800 局）。確かめにも null 16 × 26 を付ける
- null は M-6 により、調整デッキ 16 ブロックの種類のまとめ（`results/drl/p0_pool_nulls.json`）に足して更新する
  - まとめた 95% 区間が 0.5 を含まなければ止めて相談する
  - E-3a の netfree_vb どうしの null が 0.454 [0.411, 0.500] だった（D-182 §3）。本便の null は netfree_vb どうしの 2 本目なので、2 本を合わせた区間も報告に添える（判定には使わない・M-7）

### 0.4 結果 → 次の一手（設計書 §6 の表・D-164）

- 足し継ぎで「区別できない（+2% 以上は否定）」または「悪くなった」

  - 「+2% 未満の小さい改善の候補」として記録し、採らない側に倒す（M-4）。**止めて相談する**

  - **止めて相談する**（確かめには進まない）

  - **止めて相談する**（`bundle_p` の既定を 0.5 にするか・0.25 をもう 1 段測るか）。champion には触れない

  - 止めて相談する（M-6）
