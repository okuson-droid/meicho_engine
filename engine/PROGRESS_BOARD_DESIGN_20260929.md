## 3. 仕組み（データの流れ）

```
GitHub main（正本・Public）
   │  git clone --depth 1（token なし）
   ▼
定期実行のクロエ（Cowork のスケジュールタスク・1 日 2 回）
   │  切り出し → JSON（§6）→ 検算（§9）
   ▼
進行盤の db（アーティファクトの記憶）  ←  書くのはクロエだけ
   │  onSnapshot（開いた瞬間に最新を受け取る）
   ▼
進行盤のページ（読むだけ・マスターのスマホ）
```

- **ページは GitHub に触れない。**触るのは定期実行のクロエだけ。ページの中に URL 以外の GitHub の情報は置かない（リンクは `github.com/okuson-droid/meicho_engine/blob/<commit>/<path>#L<n>` の形で、commit を固定して張る＝あとで台帳が動いても行がずれない）
- **db に書くのはクロエだけ**（Owner の権限）。ページは読むだけなので、共有リンクで誰かに見せても壊されない。書き込みの規則（rules）は「全経路 admin 以上」にする
- **PC がリンクされていなくても動く。**接続フォルダは使わない。PC が眠っていても GitHub に push 済みの内容は写せる（**push を忘れると盤も古いまま**——`CLAUDE.md` の罠の 1 行目がそのまま盤に出る形になる。これは欠点ではなく、忘れを見つける仕組みとして残す）
- **定期実行が失敗したら**（clone できない・切り出しが空・db に書けない）: db の前回の内容は残し、`status` だけ `failed` と失敗の 1 行を書く。ページは前回の内容を出しつつ赤い帯で知らせる（§5）
- **ページの HTML の控え**は `engine/board/progress_board.html` として git に置く（Cowork が書き、Claude Code が commit）。アーティファクトを作り直すときの正本。**ページには秘密の値も token も無いので Public に置いてよい**（`.gitignore` にも `cards/` の除外にも触らない）

### 3.1 採らなかった経路と理由

- **GitHub Actions が JSON を作る**（§7 の「前者」）: Actions の成果物は token なしでは読めず、`main` に JSON を commit させると bot の commit が正本に混ざり、`tests.yml` が自分の commit で再び走る（`[skip ci]` で避けられるが運用が 1 つ増える）。**Actions の中でしか取れない値（検査の件数）だけを 2 回目で扱う**（§8-3）
- **ページが GitHub を直接読む**: ページは外部の URL を読めない作り（アーティファクトの制約）で、GitHub コネクタも入っていない。読めたとしても TASKS.md 88 KB をスマホで毎回パースするのは重い
- **アーティファクトでなく Claude Docs（プロジェクトの文書）1 枚**: ページを作らずに済むが、2 回目のボタンが置けず、鮮度の帯や行リンクの自動化が弱い。**進行盤が 1 回目で終わるなら悪くない選択**なので §10-1 の「ほか」に残す

## 4. 更新の頻度と費用

- **1 日 3 回・7:00・11:40・19:00（JST）**（マスター裁定 2026-09-29。クロエの推しは 11:40・21:40 の 2 回だった）。朝・昼食時・帰宅前の直前に新しくなっている。**毎時は採らない**——1 回の費用が読む分だけとはいえ、1 日 24 回で読む量は 1 便の設計書に匹敵し、見ない時間帯の更新は無駄。夜に push された分は翌朝 7:00 の盤に出る
- 1 回の仕事: clone（数秒）→ 切り出し（機械）→ JSON の検算 → db に書く → 終わり。**対局・学習・検査は回さない**。クロエが判断するのは (e) の要約 1 行だけ
- 定期実行の承認: **自動承認**が要る（誰も見ていない時間に動く）。設定できないときは「承認待ちで止まる」ので、最初の 1 回でどちらになったかを確かめる（§9）
- **止め方**: 定期実行を無効にすれば止まる。ページは最後の内容を残す

## 5. ページの設計

- **スマホ 1 列**。節は (a)〜(h) の順、各節は見出しで折りたためる。(a)〜(c) は開いた状態で始める
- **鮮度の帯**（最上部・常時）: 「2026-10-01 19:01 JST の `main`（`f76a1f9`）」。色は予定の更新時刻（7:00・11:40・19:00）を基準に決める——**次の予定時刻を 1 時間過ぎても新しくならなければ黄、2 回分過ぎたか更新失敗なら赤**（時間の長さでなく「飛ばした回数」で決める。夜の 12 時間の間隔を黄にしないため）。赤のときは失敗の 1 行を出す
- **逐語の原則**: 台帳の文は Markdown の装飾（`**`・`~~`）を落として素の文で出す。文中の `D-144` などは `decisions.md` の該当見出しへ、`engine/…md` はそのファイルへリンクする（commit 固定）
- **裁定待ちの項目**には「推し」の行を強調し、その下に「裁定はチャットで」と 1 行。1 回目はボタンを置かない
- **数字**は区間ごと写す。「V_1 − V_0 = −0.0035 [−0.0215, +0.0138]」のように。丸めない
- 色・書体は既定のまま（設計に時間を使わない）。ダークモード対応はアーティファクトの作法に従う
- **ページの JavaScript は db を読むだけ**。書き込みの口は 1 回目には入れない
- db が読めないとき（ログインしていない・権限が無い）は「進行盤を開くには claude.ai にログインしてください」だけを出す

## 7. 危険と限界

1. **要約の幻覚**。クロエが台帳を「まとめる」と、数字や主語がずれる（測定の作法の「判定を写して 2 箇所に書くと写した側が取り残される」と同じ罠）。対策: **台帳は逐語・要約は (e) の 1 行だけ・出どころ名つき・行リンク**。それでも (e) の 1 行は間違いうるので、ページに「要約は写しであり正本は報告書」と常時表示
2. **切り出しの取りこぼし**。`TASKS.md` の書き方が変わる（`- [ ] **★マスター:` の形が崩れる）と、裁定待ちが 0 件と出る。対策: 切り出しの正規表現に**検査**（§9）を置き、`TASKS.md` の `[ ]` の総数と切り出した件数が合わないときは `status: failed` にして赤で出す（黙って 0 件にしない）
3. **古い盤を信じる**。push 忘れで `main` が古いと、盤も古い。対策: 鮮度の帯に commit の**日時**を出す（「写した時刻」だけでは古さが分からない）。PC の作業ツリーと `main` の差は盤からは見えない——これは限界で、`git status` の習慣（`CLAUDE.md` 罠 1）で補う
4. **定期実行の承認モード**。無人で動くには自動承認が要る。設定できるかは作ってみるまで分からない（§9 で最初の 1 回を見る）
5. **db の書き込みが定期実行から届くか**。定期実行は新しいセッションで動くので、進行盤の URL を prompt に書いて渡す。届かなければ 1 回目の受け入れで分かる
6. **共有**。Public リポジトリの内容しか載らないので、盤を誰かに見せても新しい漏れは無い。ただし (a) の裁定待ちにはマスターの判断の途中経過が並ぶ。**盤は共有しない**のを既定にする（アーティファクトは作った時点では非公開）
7. **費用の上振れ**。clone は `--depth 1` で約 200 MB（`results/` を含む）。毎回落とすのは重い。対策: `--filter=blob:none --sparse` で `TASKS.md`・`engine/*.md`・`engine/app/*.md`・`engine/meicho/version.py`・`engine/experiments/champion.py`・`engine/experiments/seed_bands.json`・`engine/scripts/check_champion_fingerprint.py` だけを取る（数 MB）

## 8. 2 回目（1 回目が 1 週間動いてから）

1. **「推しを採用」ボタン**（§7 の本命）: (a) の各項目に「推しを採用」「ほか（チャットで）」の 2 つ。押すと db の `rulings/<id>` に `{decided: "push", at, by}` を書く（マスターだけ・Owner 権限）。**台帳への反映は自動ではしない**——次の定期実行が `rulings/` を読んで「未反映の裁定 n 件」を盤に出し、エンジンの持ち場のチャット（または PC の Claude Code）が `decisions.md` に D-番号を振って書く（`LANES.md` §3 の「D-番号はエンジンの持ち場だけ」を守る）。**盤が台帳を書くことは今後も無い**
2. **「いま更新」ボタン**: 定期実行を手で 1 回だけ起こす。アーティファクトの `mcp` の口から、マスターの claude.ai の「Claude Code Remote」コネクタの `fire_trigger` を呼ぶ形。マスターの権限で動き、ページに token は要らない。押した直後は「更新中（2〜3 分）」と出し、db が変われば自動で描き直る
3. **CI の件数**（通過・失敗・skip）: `tests.yml` の末尾で `--junitxml` を集計した 3 行を `results/ci/latest.json` に commit する（`[skip ci]`・bot の commit・`results/` だけの変更なので早送りの範囲・D-137）。定期実行はそれを読む。**これは `.github/` を触るので PC の Claude Code の仕事**
4. **アプリの持ち場の項目**（`TASKS_APP.md`・`DECISIONS_APP.md` の APP-番号）を (b)・(f) に混ぜる。1 回目はエンジンの台帳だけでもよい（§10-3）

## 9. 検査と受け入れ（1 回目）

**作る順**: 切り出しの道具とその検査 → JSON の検算 → ページ（db を読むだけ）→ 手で 1 回 db に書いて表示を見る → 定期実行を作る → 最初の 1 回を人が照合する。

- **切り出しの検査**（`engine/board/tests/`・pytest・作業環境で回す・PC の資材は要らない）:
  - いまの `TASKS.md` を入力にして、Active の `[ ]` の件数・★マスターの件数が手で数えた値と一致
  - `decisions.md` の末尾 5 件の見出しと「次の D-番号」が一致（D-144 → D-145）
  - `version.py` から `v0.19`、`champion.py` から `planner_vc4cps_kheb_b75`、指紋 `f4b80b25c35cfa77`、`seed_bands.json` から `next_free` 859000
  - **壊す側**: `[ ]` の書き方を 1 か所崩した入力で `status: failed` になる／`## D-` の行が無い入力で `next_d` が空になり `failed` になる
  - 逐語の切り出しが元の行と（装飾を除いて）バイト一致
