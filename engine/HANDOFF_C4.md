## 1. C-4 とは何か、なぜ**いま**なのか

> 固定シード・固定相手プールのガントレットと簡易Eloを整備し、以後のすべての

レビュー時点では「あとでやる整備」だったが、**B-1 の測定で優先度が上がった**。

## 2. すでにある資産（作り直さないこと）

### `experiments/arena.py` — 対戦計測の共通基盤

C-4 はこれを土台に育てるのが正しい。**新しく作り直さない。**

```python
load_deck(name="SD001") -> dict                  # decklists/*.json を読む
mirror_config(deck) -> GameConfig                # 同型戦
matchup_config(deck0, deck1) -> GameConfig       # 異型戦（席は series が入替）
ci95(wins, n) -> float                           # 1.96√(p(1-p)/n)
class Result: .p / .ci / .decided / .games / __str__
series(make_a, make_b, n, config, workers=1, seed0=0) -> Result
gauntlet(make_a, opponents: dict, n, config, workers=1, seed0=0) -> dict
report(label, r) -> None
```

すでに満たしている不変条件:

- シードは `seed0..seed0+n-1` の決定的使用（D-006）
- **先攻後攻は seed の偶奇で入替**（両方向を等しく含む）
- 引き分け・打ち切りは分母から除く（作業規約6）
- 勝率は必ず対戦数と95%信頼区間を伴う
- `workers>1` で対局単位のプロセス並列（結果は workers に依存しない）

**注意**: エージェント生成器は `ProcessPoolExecutor` に渡るので **pickle 可能**で
なければならない。lambda は使えない。各実験スクリプトが `Mk*` クラスを
定義しているのはそのためである（`measure_agents.py` の `Mk` が最小の例）。

### 現在のエージェント（すべて `meicho/` 直下）

| クラス | 生成 | 速度(単プロセス) | 位置づけ |
|---|---|---|---|
| `RandomAgent(seed)` | `agents.py` | — | 下限の基準 |
| `HeuristicAgent(seed, params=None)` | `heuristic.py` | 287 局/秒 | 規則ベース。ロールアウト方策・相手モデルも兼ねる |
| `GreedyAgent(seed, opp_decklist=POOL)` | `greedy.py` | 28.8 局/秒 | 1手先読み＋評価関数 |
| `PlannerAgent(seed, opp_decklist=POOL)` | `planner.py` | 2.1 局/秒 | **現 champion** |
| `MCTSAgent(seed, opp_decklist=POOL, iterations=160)` | `mcts.py` | 0.29 局/秒 | IS-MCTS(DUCT) |

速度は SD001同型・クラウド2コア・CPython 3.11 の実測（`bench_agents.py`）。

## 4. C-4 でやること（提案。設計は次セッションの判断に委ねる）

### 4.1 必須

1. **ガントレット定義の外出し**
   相手プール（誰と、何局、どの config、どのシード帯）を**データとして**持つ。
   いまは各スクリプトにベタ書きされていて、比較のたびに条件がずれうる。
2. **簡易Elo（またはBradley-Terry）**
   総当たりの勝敗行列からレーティングを推定する。対戦数の偏りに強い形が望ましい。
   信頼区間も出すこと（作業規約6）。
3. **結果の永続化と追記**
   `results/ladder.json` のような形で、日付・エージェント定義・シード帯・
   対戦数・勝率行列・Elo を残す。**あとから再現できること**が条件。
4. **champion の定義と更新手順**
   「現 champion に対する直接対決で有意に勝ち越したら champion を更新する」
   という運用を明文化する。有意の基準は信頼区間で（作業規約6）。

### 4.2 あると良い

- 対戦数の自動割り当て（差が小さいペアに多く割く）
- 既存の実験スクリプト（`measure_agents.py` 等）をガントレット経由に寄せる
- 非推移性の検出（A>B>C>A のような循環が出たら警告する）
  — B-1 では循環は観測されていないが、C-2（PSRO）を見据えると要る

### 4.3 やらないこと

- エージェントの強化そのもの（それは C-1 以降）
- 対H勝率の廃止（**参考値としては残す**。過去の記録との接続に要る）

## 6. 前セッションで踏んだ罠（同じ穴に落ちないために）

1. **探索に乱数を引く部品を足したら、必ず共通乱数(CRN)のスナップショット対象に
   入れる。** B-3 の相手モデルで本体の乱数を共有してしまい、分散が増えて
   勝率が −0.037 悪化した。専用乱数を CRN に入れて −0.013 に戻った。
2. **`random.shuffle` は入力の並びの関数である。** 決定化でデッキを混ぜるときは
   `sorted()` で正規化してから混ぜないと漏洩が消えない（D-026）。
3. **多重比較の偽陽性。** 26件の摂動のうち1件が下限 0.512 で有意に見えたが、
   新しいシード帯 n=500 の追試で消えた。**境界の結果は必ず別シード帯で追試する。**
4. **速度最適化でフィールドを落とす。** 高速 clone の旧案は後から足した
   `clash_counts` を複製していなかった。`test_clone_copies_every_field` が
   全フィールドを突き合わせて検出する形になっている。
5. **同型自己対戦だけで規則の寄与を判断しない**（A-4）。用途を変えると判定が変わる。
