## この文書の読み方

マスターから出た案（2026-08-27）:

> 2,000 種類以上あるカードの特徴（攻撃力、コスト、特殊効果のテキストなど）を、
> 自然言語処理の技術（Word2Vec の応用など）を使って数十次元のベクトルに変換します。
> これにより、AI は「カード A とカード B は似た性質を持っている」という関係性を
> 理解した上で構築を行えます。

§0 が判定。§1 が用語（「埋め込み」とは何か）。§2 が**実測**——いまのカードで、
この案が埋めようとしている穴が実際にどれだけ空いているかを数えた。
§3 が「Word2Vec でなくオペコードを使うべき理由」。§4 が規模の話（2,000 種はまだ来ていない）。
§5 が「デッキ構築に効くか」（案が挙げている用途の方）。§6 が段取りと測り方。

数字の読み方: 勝率の ± は 95% 信頼区間（同じ条件で測り直したら収まる幅）。

## 0. 判定（先に）

**方向は正しい。というより、この案が指している穴は計画にすでに書いてあり、
しかも測ってみたら想像より大きく空いていた。** ただし中身は 3 点、案と変える。

| 案の要素 | 判定 | 理由 |
|---|---|---|
| カードをベクトルで表す | **採用**（すでに `DRL_PLAN.md` §3 の「効果プロファイル射影」として計画済み） | 初見カード・別プールへの転移に必要。§2 で穴の大きさを実測した |
| **Word2Vec でテキストから作る** | **不採用** | このゲームには**効果オペコードという実行可能な正確な仕様**がある（エンジンがそれを実行している）。テキストは近似、オペコードは厳密。加えて公式テキストの複製はプロジェクトの制約に触れる |
| 2,000 種を前提に数十次元へ圧縮 | **時期尚早** | 登録簿はいま **53 種**（キャラ 18・アクション 35）。この規模ではワンホット（1 種 1 枠）の方が鋭い。着手条件は「プールが実際に増えたら」 |
| デッキ構築に使う | **主用途にしない** | 「似ている」は勝率より弱い信号。デッキの選別はガントレットで測るのが本筋（§5） |

**そして、いちばん重要な発見。**

> **第一手は埋め込みですらない。**
> いまの符号化は、**機構としてまったく同じカードを、完全な別物として扱っている**。
> SD001 と SD02 は「カード ID の共通が 0 種」だが、**機構の仕様で数えると
> アクション 17 種中 7 種・キャラ 9 種中 2 種が共通**である。
> 一致しない理由は**専用キャラが違うことだけ**（漂泊者（女）／漂泊者（男）など）。
> ここを直すのは埋め込みの学習ではなく、**符号化の分解のしかた**の問題であり、
> 学習を 1 回も回さずにできる。

## 1. 用語: 「埋め込み」とは何か

カード 1 枚を、数値の並び（ベクトル）1 本で表すこと。表し方には 2 通りある。

- **ワンホット（1 種 1 枠）**: カードの種類ぶんだけ枠を用意し、そのカードの枠だけ 1、他は 0。
  いまの `encode.py` がこれである（`A_INDEX` がカード ID → 枠番号の表）。
  **鋭い**（違うカードは必ず違う値）が、**見たことのないカードには枠が無い**。
- **素性から作るベクトル**: 「色は赤」「コストは 2」「【判定】で回復する」といった
  **カードの性質**を並べる。**鈍い**（似たカードが似た値になる）が、
  **初見のカードでも値が作れる**。

案が言っているのは後者である。`DRL_PLAN.md` §3 はこれを
「カード ID ごとに学習するもの（鋭いが初見に効かない）と、効果プロファイルから作るもの
（鈍いが初見に効く）の**2 本立て**にする」と書いていて、**片方を捨てる話ではない**。
この点で案と計画は一致している。

## 2. 実測: 穴はどれだけ空いているか（`analyse_card_space.py`）

カード ID もカード名も専用キャラ名も一切使わず、**機構の仕様**
（色・コスト・速度・打点・タグ・誘発タイミング・条件・効果オペコード列とその引数）
だけでカードを表し直して、2 つのプールの共通部分を数えた。

### 2.1 数え方を変えると、共通枚数が変わる

| | ID で数える | 名前で数える | **機構の仕様で数える** |
|---|---|---|---|
| アクションカード（17 種中） | **0** | 7 | **7** |
| キャラカード（9 種中） | **0** | 0 | **2** |

D-058 が「共通 0 種」と記録したのは **ID で数えた値**である。
**「カード ID が違う」と「カードが違う」は同じではない。**

### 2.2 一致した 9 組の中身

機構の仕様が完全に一致した組は、登録簿全体で 9 組あった。
**そのすべてが「専用キャラだけが違う同じカード」である。**

| | | 違い |
|---|---|---|
| SD001-T01 音の形・通常攻撃 | SD02-T01 音の形・通常攻撃 | 専用キャラ 漂泊者（女）／（男） |
| SD001-T02 轟音 | SD02-T02 轟音 | 同上（効果中のキャラ名も対応して違う） |
| SD001-T15 スキャン | SD02-T15 スキャン | 同上 |
| SD001-T12 音の形・回避 | AC-002 音の形・回避 | 同上 |
| SD001-T16 鉤縄 | AC-004 鉤縄 | 同上 |
| SD001-T13 羽の刃・回避 | SD02-T13 冷徹な光・回避 | 専用キャラ 秧秧／散華（**名前も違う**） |
| SD001-T06 息継ぎ | AC-007 凛然浄化 | 同上（**名前も違う**） |
| SD001-C01 漂泊者（女） | SD02-001 漂泊者（男） | キャラ名だけ |
| SD001-C02 漂泊者（女） | SD02-002 漂泊者（男） | キャラ名だけ |

**この 2 つのスターターデッキは、同じデッキのキャラを入れ替えたものである。**
下 2 組（羽の刃・回避／冷徹な光・回避、息継ぎ／凛然浄化）は**名前まで違う**ので、
名前を鍵にしても繋がらない。**機構で表さないと繋がらない。**

### 2.3 表現は情報を捨てていないか

捨てていない。名前が同じでも中身が違うカードは、ちゃんと分かれる。

| | 色 | コスト | 速度 | 打点 | 専用キャラ |
|---|---|---|---|---|---|
| SD001-T03 音の刃 | 赤 | 1 | 16 | 1 | 漂泊者（女） |
| AC-003 音の刃 | 赤 | 1 | **13** | **3** | 漂泊者（男） |

**捨てているのは「誰のカードか」だけで、それは別枠（キャラの添字）で持てばよい。**
`tests/test_card_space.py` が「一致した組の違いは card_id / name / dedicated_to / skills に限られる」
ことを検査で固定している（カードが増えても数値ではなく性質を見るので落ちない）。

### 2.4 素性の共通率（転移させうる情報量の上限）

| | SD001 | SD02 | 共通 |
|---|---|---|---|
| 全素性（パラメータ込み） | 91 種 | 83 種 | **68 種（SD001 側の 75%・SD02 側の 82%）** |
| 効果オペコード | 16 種 | 15 種 | 11 種 |
| 誘発タイミング | 5 | 5 | 4 |
| 誘発条件 | 4 | 4 | 3 |
| タグ | 16 | 15 | 12 |
| 色 / コスト | 3 / 4 | 3 / 4 | 3 / 4 |

**カード ID で見れば 0%、素性で見れば 75〜82% 共通。** これが「埋め込みが転移させうる情報」の上限である。

### 2.5 これが D-058 の 0.449 をどう説明するか

SD001 で学習した π を SD02 に持ち込むと **0.449 ±0.028**（何もしないより悪い）だった。
機構がこれで説明できる。SD02 の盤面を SD001 産のネットに見せると、
**カードの枠が全部ゼロ**になる。ネットから見て「手札が空で、協奏も墓地も空の盤面」に見える。
そこで返る値は意味のある予測ではなく、**学習していない領域のでたらめ**である。
既定の相手モデル（H で埋める）は少なくとも規則としては正しく動くので、それより悪くなる。

**7/17 のカードは機構としてまったく同じものだったのに、ネットは一度もそう扱えていない。**

## 3. なぜ Word2Vec ではなくオペコードか

Word2Vec は「**周りに出てくる語が似ていれば似た意味**」という仮定で単語をベクトルにする技術である。
文章しか無いときには強力だが、このプロジェクトの状況では 3 つの点で劣る。

1. **すでに正確な仕様がある。** `cards.py` の効果は 20 種のオペコード列であり、
   **エンジンがそれを実行して対局が成立している**。テキストは仕様の**説明**であって仕様そのものではない。
   説明から近似的に意味を推定するより、仕様を直接使う方が正確である。
2. **テキストの類似は機構の類似と食い違う。** 「手札を 1 枚引く」と「手札を 1 枚捨てる」は
   語の重なりが大きいが、盤面への作用は逆である。逆に「羽の刃・回避」と「冷徹な光・回避」は
   語がほとんど重ならないが、**機構としては同じカード**である（§2.2）。
   Word2Vec はこの 2 つをどちらも取り違える。
3. **公式テキストの複製を含む成果物を作らない**というプロジェクトの制約がある。
   オペコードは自分たちで書き起こした仕様なので、この問題が無い。

**Word2Vec が要るのは、オペコード化が追いつかないときだけである。**
発売後（2026-09-12）にカードが大量に入って、テキストの読み取りは済んだがオペコード化が
未了、という状態が来たら、そのときは「テキストから暫定のベクトルを作り、unverified 扱いで使う」
という使い道はありうる。だが**それは今の話ではない**。

## 4. 規模の話（2,000 種はまだ来ていない）

いまの登録簿は **53 種**（キャラ 18・アクション 35）である。案が前提にしている 2,000 種は、
**発売後にカードプールが育った将来の姿**であって、現状ではない。

埋め込みが効くのは「種類が多く、1 種あたりのデータが薄い」ときである。
逆に**種類が少ないうちは、1 種 1 枠のワンホットの方が鋭くて強い**。
いまのネットが `NA = 35` 枠でカードを持っているのは、その意味で正しい設計である。

**着手条件を先に決めておく。**

| 条件 | 中身 |
|---|---|
| いま（53 種） | ワンホットのまま。**§6 の第 1 段（機構による分解）だけやる**。学習は要らない |
| プールが数百種に育ったら | 素性ベクトルをワンホットと**併用**する（2 本立て・`DRL_PLAN.md` §3） |
| 1 種あたりの対局数が薄くなったら | 素性ベクトルを圧縮する（このとき初めて「数十次元」の話になる） |

## 5. デッキ構築に効くか（案が挙げている用途）

案は「関係性を理解した上で構築を行える」と書いている。ここは分けて考える必要がある。

**効く場面**: 候補が多すぎて全部は試せないとき、似たカードをまとめて**探索空間を減らす**用途。
発売後にプールが育って「40 枚を 2,000 種から選ぶ」になったら、これは要る。

**効かない場面、というより誤導しうる場面**: 「似ているから同じくらい強いはず」と考えること。
このプロジェクトにはすでに反例がある。`deck_structure.md` に記録した
**「赤 55% はプール強制の下限で、その大半は常に死に札」**という発見は、
カードの類似度からは絶対に出てこない。出したのは**シミュレーション**である。

したがって:

> **埋め込みは「何を試すかを絞る道具」であって、「どれが強いかを決める道具」ではない。**
> 強さを決めるのは、いまも将来もガントレット（ロードマップ段階 5）である。

## 6. 段取り（推す順）

### 第 1 段（いますぐできる・学習は要らない）— カードを (機構) × (誰の) に分解する

符号化のカード枠を、いまの「カード ID ごとに 1 枠」から
**「機構の仕様ごとに 1 枠」＋「専用キャラの添字」**に変える。
§2.2 の 9 組がこれで繋がる。埋め込みの学習も、次元圧縮も、NLP も要らない。

- 費用: `encode.py`（真実源）と `encode.rs` を変え、`ENCODING_VERSION` を上げ、記録を作り直す。
  半日 ＋ 記録の再生成 6 分。
- **測り方**: SD001 で学習した π を **SD02 に持ち込んで**測る。
  現行（ワンホット）の値 **0.449 ±0.028** が対照になる。これを 0.5 以上に持ち上げられるかどうか。
  D-058 と同じ帯を避けて別帯で取る。
- **効かなかったときに分かること**: 「転移しない理由はカードの表現ではない」。これも収穫である。

### 第 2 段（プールが育ってから）— 素性ベクトルの併用

ワンホットを残したまま、素性ベクトル（§2.4 の 68 種の共通素性）を第 1 層に足す。
`DRL_PLAN.md` §3 の 2 本立てそのもの。

- **測り方**: **隠しカード検査**（`PRERELEASE_GOAL.md` §1.2）。
  台帳からカード X を隠して学習し、X を含むデッキで X を正しく使えるかを対局で測る。
  ワンホットだけの版が対照になる（そちらは原理的に使えないはずで、
  **その差がそのまま埋め込みの価値**である）。

### 第 3 段（1 種あたりのデータが薄くなってから）— 圧縮

ここで初めて「数十次元」の話になる。圧縮の材料は素性ベクトルであって、テキストではない。

### 守ること

**「似ているように見える」を進捗と呼ばない。**
埋め込みは、コサイン類似度を並べると納得のいく絵が出やすい種類の技術である。
だが、このプロジェクトは同じ形で 4 回失敗している
（D-038 の回帰・C-1 の線形版・段階 1 の V・段階 2 の π——いずれも
「予測は良くなったが強くならなかった」）。
**採用の物差しは、隠しカード検査と対局の勝率だけである。**
