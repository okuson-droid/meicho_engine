## 0. 一行で

**カードを画像で並べ、手に取る代わりに拡大して読む。** ルールも合法手も記録も一切変えない。
エンジンのオペコード言い換え文（現行の検証機能）は拡大パネルとトグルで残す。

## 1. 目的と非目的

### 1.1 目的

1. **実卓に近い体験で打てること。**
   [[prerelease_goal]] の一次基準は「マスター対 AI の直接対局」である。画面が実卓と違いすぎると、
   **測っているのが実力差なのか画面の読みにくさなのかが分離できない。** 体験差を測定のノイズから外すのが本題。
2. **現行の検証機能を失わないこと。**
   画面に出ているスキル文は**カードテキストの転記ではなくエンジンのオペコード列の言い換え**であり、
   実装とテキストの食い違いを見つけるのが目的だった（`webapp/README.md`）。
   画像を出すと公式テキストが読めてしまい、この機能は**放っておけば消える**。消さない設計にする。

### 1.2 非目的（今回やらないこと）

- カードの移動・ダメージ・レベルアップの**アニメーション**（マスター裁定でレイアウトと拡大までとした）
- 対抗ステップの**同時公開演出**（自分の提出を伏せて置き、CPU と同時にめくる）
- 段階2 レビュー画面（`webapp/review.py` の 1 枚 HTML）の画像化
- 画像を含む成果物の公開（プロジェクト制約。**本書にも画像を貼らない**）
- 画像から数値を読み取る OCR による照合

非目的のうち上 2 つは**後から足せる形**にしておく（§10）。

## 2. 前提の調査結果（実測・2026-08-31）

設計の根拠になる事実を先に置く。**推測ではなく実ファイルを数えた値である。**

| 事項 | 実測値 |
|---|---|
| `cards/` の PNG | **76 ファイル** |
| うち異なるカードID | **65 種** |
| `cards_structured.json` の行数 | 76 行（**11 行は同一 ID の重複**） |
| 画像の無い実装カード | **0 枚**（JSON の全 ID に画像がある） |
| 画像の寸法 | 315×440 〜 334×467 px |
| 縦横比 | **0.715**（実カード 63×88 mm = 0.716 とほぼ一致） |
| 1 枚の大きさ | 165〜320 KB（合計 **約 18 MB**） |

### 2.1 `-R` はパラレル（レアリティ違い）である

`BP01-003_ツバキ_LV1.png` と `BP01-003_ツバキ_LV1-R.png` のように 11 組が対になっている。
JSON を突き合わせると、**同じ ID・同じ効果テキストで `rarity` だけが 1 と 2 で異なる行**が対応する。
すなわち `-R` は**別カードではなく別イラスト（パラレル仕様）** である。

→ **既定は `-R` の無い方を使う。** ゲーム上は完全に同じカードなので、どちらを出しても対局には影響しない。

### 2.2 画像ファイル名の誤りは、この改修で問題にならなくなる

[[card_reconciliation]] の残作業に「画像ファイル名の直し 11 件」（`秋秋`→`秧秧` の誤字、
`鈎縄`→`鉤縄` の異体字、`_LV1` の欠落）がある。
本設計では**ファイル名の先頭のカードID だけを見て索引を作る**ので、名前の残りが何であっても正しく引ける。

→ **改名は不要になる。マスターの手作業が 1 件減る。**（直したければ直してよい。索引は壊れない。）

### 2.3 未登録 13 枚

`cards/` には画像と JSON 行があるが `meicho/cards.py` に無いカードが 13 枚ある（D-062 §残作業）。
これらは**どのデッキにも入らないので画面には出ない。** 索引には載せるが未使用のまま置く。

## 3. 設計方針（原則）

改修中に迷ったらここに戻る。

| # | 原則 | 意味 |
|---|---|---|
| **P1** | **画面はルールを持たない** | 現行方針の維持。押せる手は `legal_actions()` の一覧をそのまま並べる。画像はただの見た目であり、判断に一切関わらない |
| **P2** | **画像は `observe()` に無い情報を持ち込まない** | **最重要。** 相手の手札・両デッキ・相手のキャラデッキは裏面で描く。画像索引は ID を要求するが、ID を持たない場所に画像を出してはならない |
| **P3** | **画像が無ければ必ずテキストに落ちる** | 現行のテキストカードをフォールバックとして残す。**黙って消えるカードを作らない** |
| **P4** | **エンジン文を消さない** | 拡大パネルには常にエンジン文を併記する。画像だけしか見られない状態を作らない（§6） |
| **P5** | **画像とエンジンの食い違いは機械で見張る** | 人間の目視に頼らず、索引の網羅をテストで固定する（§7） |
| **P6** | **記録は 1 バイトも変わらない** | 表示設定は `results/human_games/*.jsonl` に一切書かない。改修前後で同じ行動列なら同じ記録になること |

## 4. データの流れ

```
cards/*.png ──(起動時に1回走査)──> webapp/images.py: INDEX {card_id: filename}
                                        │
                                        ├─> view.py: カード dict に "img": "/card/SD01-009.png" を足す（無ければ null）
                                        │        ※ 既存の項目は一切削らない（テキスト表示がそのまま生きる）
                                        │
                                        └─> server.py: GET /card/<ID>.png で INDEX 経由で配信
```

### 4.1 `webapp/images.py`（新規・約 60 行）

```
CARDS_DIR = <リポジトリ>/cards        # engine/ の兄弟。engine/ の外にあることに注意
_ID_RE    = ^([A-Z]{2}[0-9]{2}-[0-9]{3})

build_index() -> dict[str, str]
  1. CARDS_DIR の *.png を走査
  2. ファイル名の先頭に _ID_RE が当たるものだけ拾う（当たらないファイルは無視）
  3. 同じ ID が複数あれば「-R を含まない方」を採る。両方 -R なら辞書順の先頭
  4. {card_id: 絶対パス} を返す

path_for(card_id) -> str | None
```

**索引はプロセス起動時に 1 回だけ作る。** 対局中にフォルダを見に行かない
（対局の途中でファイルが増減しても表示が揺れない。決定性の方針と揃える）。

### 4.2 サーバ経路 `GET /card/<ID>.png`

- **ID の書式検査だけを行い、パス結合はしない。** 索引の辞書から引く。
  → 経路文字列からファイルパスを組み立てないので、フォルダ横断の危険が構造的に無い。
- 見つからなければ `404`。画面はテキスト表示に落ちる（P3）。
- ヘッダ: `Cache-Control: public, max-age=31536000, immutable`
  **現行の `no-store` は API 応答にだけ残す。** 画像に効かせると 1 手ごとに 18 MB を読み直し、
  低スペック PC で確実に体感が落ちる。カード画像は内容が変わらないので恒久キャッシュでよい。

### 4.3 `view.py` の変更（+10 行程度）

`action_card()` / `chara_card()` の返す dict に `"img"` を足すだけ。**既存の項目は削らない。**
`skills`（エンジン文）も `label` もそのまま返す。これが P4 の担保になる。

### 4.4 裏面

**実物の裏面画像は無い。** 相手の手札・デッキ・相手のキャラデッキの非公開枠は
**CSS で描いた裏面**（`.cardback`）を使う。表面と同じ比率・同じ角丸で、中央に薄く紋様を置く。

- 相手の手札は `hand_count` 枚ぶんの裏面を並べる。**枚数が形で見える**のが実卓に一番近い。
- デッキは厚みのある 1 枚（枚数を数字で重ねる）。
- **裏面には ID を一切持たせない**（P2。DOM に ID が残ると開発者ツールで覗ける）。

## 5. 画面（レイアウト）

### 5.1 全体

現行の上下配置を変えない。**変えるのは「枠＋文字」を「画像タイル」に置き換える点だけである。**

```
┌ 上バー（対局ID・シード・ターン・ボタン）
├ CPU ─ ヘッダ（ライフ／手札／協奏／トラッシュ／デッキ）
│      キャラ枠 3 つ（画像・重ねは少しずらして描く）
│      アクションエリア（画像）
│      協奏エリア（画像）
│      手札（裏面 × 枚数）      ← 新規。実卓の見え方に合わせる
│      判明した手札（あれば・表向き画像／青枠）
├ 中央 ─ 継続効果・履歴 ／ ログ
├ 自分 ─ ヘッダ
│      キャラ枠 3 つ
│      アクションエリア／協奏エリア
│      手札（表向き画像・大きめ）
├ 自分のキャラデッキ一覧（C キーで開閉・画像）
└ 行動一覧（現行のまま。1〜9 / ↑↓ Enter）
```

### 5.2 寸法

CSS 変数ひとつで全体が拡縮するようにする。

```
--cw: 88px;                     /* カード幅の基準 */
--ch: calc(var(--cw) / 0.716);  /* = 123px。実カード 63:88 の比 */
```

- 場・協奏・キャラ枠: `--cw`
- 自分の手札: `calc(var(--cw) * 1.2)`（一番よく見るので大きく）
- 相手の手札（裏面）: `calc(var(--cw) * 0.8)`
- `object-fit: contain` ＋ 濃いグレー背景。画像ごとの寸法の揺れ（315×440 と 334×467）を吸収する。

### 5.3 手札は扇状にしない

実卓では手札を扇状に持つが、**画面で重ねると読めずクリック位置もずれる。**
等間隔で並べ、枚数が増えたら `--cw` を自動で詰める（最小 64px）。
**「実卓に近い」は「操作を悪くする」ではない。**

### 5.4 キャラ枠の重ね

レベルアップで重ねたカードは、**下のカードを数 px ずつ下にずらして描く。**
実卓と同じ見え方であり、しかも「何枚重なっているか」が形で分かる。
下のカードのスキルも有効（§6.3-3）なので、**拡大パネルには重なり全部のエンジン文を出す**（現行と同じ）。

### 5.5 数値は残す

ライフ・手札枚数・デッキ残・トラッシュ・協奏枚数の**ヘッダ表示は現行のまま残す。**
画像だけでは山札の残りなどが分からず、実卓より情報が減ってしまう。差分の ▲▼ 表示も残す。

## 6. 拡大（実卓で手に取る代わり）

**これが「エンジン文を残す」仕掛けを兼ねる。**

**規則はひとつだけ: マウスがカードに乗っている間だけ出る。**（v1.3 で改めた）

| 操作 | 動き |
|---|---|
| カードにマウスを乗せる | 0.15 秒後に拡大パネルが出る |
| カードから離す | **消える** |

v1.2 では「クリックでピン留め」と「↑↓ で選んだ行動のカードを自動で拡大」も入れていた。
**どちらも拡大が居座る状態を作るので外した**（§15.6）。
盤面が覆われて読めず、操作もしにくい。ピン留めが無くても、
乗せている間はずっと読めるので不足しない。

拡大パネルの中身は**左に画像（原寸 334×467 の 1.5 倍まで）・右にエンジンの数値とスキル文**を並べる。

```
┌─────────────┬──────────────────────────┐
│             │ SD01-009 躍動する炎        │
│  カード画像  │ 赤 / コスト0 / 速0 / ダメ0 │
│  （拡大）    │ ─────────────────────── │
│             │ 【連撃】自分のリーダーを… │← エンジンのオペコード言い換え
│             │ ※ カード画像の文面と読み  │
│             │    比べること              │
└─────────────┴──────────────────────────┘
```

**この並びが検証機能の本体である。** 画像（＝公式テキスト）とエンジン文が常に隣り合うので、
食い違いは「読み比べる」だけで見つかる。**むしろ現行のテキストのみより見つけやすい。**
食い違いを見つけたら現行どおり `F` キーで印を付ける。

パネルは画面外にはみ出さないよう上下反転させる。

## 8. 操作

### 8.1 変えないもの

`1`〜`9` / `↑↓` と `Enter` / `C`（キャラデッキ開閉）/ `F`（気になる印）/ マリガンの入切と `Enter` /
投了 / 記録して終了。**既存の手癖を壊さない。**

### 8.2 足すもの

| キー | 動き |
|---|---|
| `Z` | **エンジン文の常時表示トグル。** 押している間ではなく、押すたびに入切。全カードの下にエンジン文が出る（＝現行の見た目に戻る） |
| `+` / `-` | カードの大きさ（`--cw`）を 8px 刻みで変える（64〜140px） |

拡大を閉じるキーは要らない（マウスを離せば消えるため）。

`Z` と `+/-` の状態は `localStorage` に持つ（ローカルのブラウザなので使える）。
**ただし表示設定だけである。** 対局の状態・記録には一切入れない（P6）。

### 8.3 マリガン

現行の「カードごとに戻す／残すを入切する」方式を変えない。
**カード画像の上に「戻す」の帯を重ね、戻す札は暗く沈める。** 数字キーとクリックは現行どおり。

## 9. 性能

- 合計 18 MB。**恒久キャッシュ（§4.2）で初回だけ読む。** 2 局目以降はネットワークが動かない。
- DOM の数は現行と変わらない（1 局面あたりカード 40 個前後）。増えるのは `<img>` 1 個ずつ。
- `loading="lazy"` は**使わない**。枚数が少なく、遅延読み込みのちらつきの方が害になる。
- **縮小版の生成は今はやらない。** Pillow 依存が増えるうえ、恒久キャッシュで足りる見込み。
  実測して遅ければ `scripts/make_thumbs.py` を後から足す（判断は測ってからにする。[[measurement_discipline]]）。

## 10. 後から足せるようにしておくこと

今回作らないが、構造だけ潰さないでおく。

- **対抗の同時公開演出**: 自分の提出を伏せて置き、CPU の提出と同時にめくる。
  → 対抗ステップの描画を「提出済み（伏せ）」「公開済み」の 2 状態に分けられる形にしておく。
  現行の同時手番の構造（`decision_players` が揃ってから `apply`）とは無関係であり、**エンジンには触らない**。
- **アニメーション**: カード要素に安定した `data-card-id` を付けておけば、後から差分アニメを足せる。
- **レビュー画面の画像化**: `review.py` は 1 枚 HTML を吐くので、画像は `<img src="file://...">` 参照か
  data URI 埋め込みかの判断が要る（埋め込むと 1 局で数 MB になる）。段階2 の課題として残す。

## 12. 作業の順序（**分割しない**・裁定 Q5）

**A〜D をまとめて 1 回で打ち切る。** 途中で対局して作り込み量を決め直すことはしない。
ただし**作業する順序は下の A→B→C→D を守る**（後ろは前に依存する）。

| 順 | 内容 |
|---|---|
| **A** | 索引・`/card/` 経路・場と手札の画像化・裏面・フォールバック |
| **B** | 拡大パネル（エンジン文の併記）・`Z` トグル・`+/-` |
| **C** | キャラデッキ一覧（`C`）とマリガン画面の画像化 |
| **D** | `check_card_images.py`・README 更新・`decisions.md` D-063 記録 |

プロジェクト規約 5 に従い、**A の実装より先に §7.2 のテストを書く。**

**分けないことの帰結（承知のうえで進める）:**
実卓と違うと感じた点が出るのは**全部作り終えてから**になる。そこで出た指摘は

### 15.6 v1.3: 拡大が居座っていたのを直した（2026-08-31・マスターの指摘）

**症状**: 拡大パネルが出たまま消えず、盤面が読めない・操作しにくい。

**原因は 2 つあり、片方は素朴な CSS の見落としだった。**

1. **`.zoom { display:flex }` が `hidden` 属性に勝っていた。**
   `hidden` はブラウザ既定の `display:none` にすぎず、クラスの `display` に負ける。
   つまり**隠す指示は最初から一度も効いていなかった。**
   → `.zoom[hidden]{display:none}` を明示。
2. **`syncSel()` が描き直しのたびに拡大を出し直していた**（キーボード用の自動拡大）。
   仮に 1 を直しても、これがある限り出っぱなしになる。
   → 自動拡大とピン留めを**やめた**。

**足した受け皿**: カードの上にマウスがあるまま盤面を描き直すと、
消えた要素の `mouseleave` は**二度と来ない**。
そこで「どのカードにも乗っていないのに出ている」状態を `mousemove` で毎回畳む。
スクロール時にも畳む。

**検査（2 件追加。合計 17 件）**
- `test_zoom_panel_can_actually_be_hidden`: `.zoom[hidden]{display:none}` があること
- `test_zoom_has_no_sticky_state`: `mouseleave` と `mousemove` があり、`pinned` が無いこと

**自動操作で確かめた 6 点**（すべて期待どおり）: 盤面が出た直後は出ていない／
乗せると出る／離すと消える／クリックしても留まらない／
**乗せたまま 1 手打っても居座らない**／↑↓ で選んでも勝手に出ない。

**教訓**: `hidden` 属性で隠す要素に `display` を効かせるクラスを当てるときは、
`[hidden]` の打ち消しを必ず書く。書き忘れても**画面上は「たまたま出ている」だけ**で、
JS 側は正しく隠したつもりでいる。

## 16. v1.4: 行動をカード画像のクリックで選ぶ／トラッシュを開く（マスターの指摘）

### 16.1 トラッシュは公開情報なので、いつでも中身を見られるようにした

`rules_draft.md` §11 の隠蔽情報は「相手の手札・両デッキの順序・準備段階のキャラ配置」だけである。
**トラッシュは両者とも公開情報**であり、`observe()` は最初から中身を返していた。
画面が枚数しか出していなかっただけなので、**情報は増えていない。**

- ヘッダの「トラッシュ n 🔍」を押すとモーダルで一覧が出る（自分・CPU の両方）。
- 中のカードにもマウスを乗せれば拡大とエンジン文が出る。
- 背景クリックか `Esc` で閉じる。

### 16.2 行動は「何をするか」→「対象をクリック」の 2 段にした

実卓では「チャージする」と決めてから手札を選ぶ。それに合わせた。

| 段 | 出るもの |
|---|---|
| 1 | **何をするか**のボタン列（チャージ／レベルアップ／リーダーを切り替える／対抗フェイズへ進む／ターンを終える…） |
| 2 | 対象になるカードが**黄色く縁取られ、番号が付く**。クリックか数字キーで決まる。`Esc` でやめる |

対象の置き場は種類ごとに決まる。

| 種類 | 対象 |
|---|---|
| チャージ／対抗に出す／連撃する／手札を捨てる | **自分の手札** |
| レベルアップ | **キャラデッキ一覧**（★ の札。自動で開く） |
| リーダーを切り替える／リーダーにするキャラを選ぶ | **自分のキャラ枠** |

レベルアップは「キャラを選ぶ → 捨てる手札を選ぶ」の 2 回のクリックになる。
これはエンジンがそういう順で聞いてくるからであり、**画面が段取りを作ったのではない。**

### 16.3 それでも画面はルールを持たない（ここが肝）

見た目は変わったが、**画面がやっているのは「種類と対象の組から `s.legal` の添字を引く」ことだけ**である。

- 種類は合法手の `type` をまとめたもの。**画面が種類を発明していない。**
- 対象の識別子は合法手そのものから取る（`action.hand` / `action.card` / `action.back`）。
- サーバに送るのは**添字だけ**（`/api/play {index, ply}`）。行動の中身は組み立てない。
- まとめ方を知らない種類（キャラ配置・「何枚にする」など）は、
  **その手そのものをボタンにして必ず出す。**
- それでも押せるものが 1 つも作れなかったときは、
  **合法手そのままの一覧（`L` キー）が自動で開く**（§5.6 の安全網）。

### 16.4 轟音の画像が別のカードだった（データの問題・**マスターの手作業が要る**）

`cards/SD01-019_轟音.png` は `cards/SD01-018_音の形回避.png` と**バイト単位で同一**だった。
取り込みのときに複製されたもので、**轟音の画像は一度も入っていない。**

画像そのものは直せないので、**仕組みで気付けるようにした**:

- `images.duplicate_groups()` が「別の ID が同じ中身を指している」組を見つける。
  パラレル（`-R`）は別イラストなので中身が違う。**中身の一致は必ず取り込みの事故である。**
- 開始画面と対局中のバーに出す。
- `tests/test_card_images.py` が**新しい重複が増えたら落ちる**。
  既知の 1 件は `KNOWN_DUPLICATES` に書いてあり、**直したらそこを空にする**
  （空にし忘れないよう、直ると別の検査が落ちて教える）。

### 16.5 確かめたこと

- **クリックだけで 1 局を最後まで打てる**ことを自動操作で 5 局確認（一覧 L は使わない）。
  チャージ・レベルアップ・切り替え・リーダー選択・対抗の提出・パス・連撃・連撃中止・
  手札を捨てる・効果を使う／使わない・「何枚にする」・キャラ配置まで、全部の種類を通った。
  詰まった局面は 0。JS のエラーも 0。
- トラッシュのモーダルが自分・CPU の両方で開き、`Esc` で閉じる。
- **改修前と同シード 24 局の行動列が一致**（v1.2 と同じ検査を再実行）。
- 検査は 47 件通過（新規 21 件）。

### 16.6 ついでに直った古い不具合

`[hidden]{display:none !important}` を全体に入れた。
`hidden` 属性は `display` を持つクラスに負けるので、
**「判明した手札」の空欄が常に出ていた**（`.zone{display:flex}` に負けていた）。
拡大パネルと同じ原因である（§15.6）。同じ罠を三度踏まないよう、まとめて打ち消した。

## 17. v1.5: ログで「何に使ったか」を書き分ける（2026-09-01・マスターの指摘）

### 17.1 何が読めなかったか

連撃や対抗では、**コストとして支払った札と、実際に使った札が、同じトラッシュに並ぶ**。
ログはどちらも `→ CPU のトラッシュに <カード>` としか書かなかったので、
**相手が何を使ったのかが読めなかった。**

### 17.2 区別できる材料は観測にあった（情報は足していない）

1 回の `apply` で領域がどう動くかを**実測**した（推測で書かない）。

| 減った領域 | 増えた領域 | 意味 |
|---|---|---|
| 協奏エリア | トラッシュ | **コストの支払い** |
| アクションエリア | トラッシュ | **使い終わった札** |
| 手札 | トラッシュ | 捨て札（手札コスト・手札上限） |
| 手札 | アクションエリア | 場に出した（対抗の提出・連撃） |
| 手札 | 協奏エリア | チャージ |
| （どこからでもない） | 協奏エリア | **デッキの上から置かれた**（効果） |

`webapp/session.py::card_moves()` が、
「その apply でどの領域から同じカードが減ったか」から出どころを引く。
**観測に写っているものしか使っていない。**

相手の手札は観測に写らないので、`hand_count` の**減りぶんを上限**として
「手札から」に割り当てる（枚数は公開情報）。
減っていなければ「手札から」とは書かない（**でっち上げない**）。

同じ ID の札が複数の出どころから同時に動くと、どちらがどちらかは区別できない。
ただし**付く説明の集合は正しい**（1枚がコスト、1枚が使用済み）ので読む上の実害はない。
